# Project format and conversion plan

The current scope covers saved projects and import/export through the CLI and desktop menus. Live editing is deferred.

## Host capabilities and deferred live editing research

I found no documented workflow in which MPCut can repeatedly overwrite an open native project on disk and all three editors will incorporate those edits. Each editor owns its active document. Use a separate file for exchanging revisions, then apply each accepted change through the running editor where its API permits it.

### Stills in project conversion

- A `.cut` copy preserves the typed still placements and relative media references in the current state and retained history.
- FCPXML and FCPXML bundles can represent opaque SDR JPEG, PNG and TIFF inserts with centered Fit or Fill at the destination frame cadence. Each insert is a primary-storyline video item linked to the original image, with its own exact duration and no audio component. The following recording starts after that interval. This mapping works for a sequence, multicam assembly with retained group ranges, or a still-only sequence with a declared canvas. MPCut metadata retains placement identity, asset identity, and the source fingerprint when the receiving tool preserves that metadata. [Apple’s FCPXML DTD](https://developer.apple.com/documentation/professional-video-applications/document-type-definition)
- Replace Picture placements, unsupported insert framing, color, format or timing, and stills in Premiere and Resolve archive conversion require explicit conversion-loss approval. Approved omission removes an insert and its silent interval or restores the original picture under a replacement. Resolve timeline handoff reports unsupported placements before writing. The Final Cut Pro library route uses FCPXML and requires a host import to verify playback.

## Shared converter design

1. **Define the MPCut document.** A `.cut` JSON document identifies its format, schema version and kind. Sequence and multicam edits use the same extension. A separate `.cutdb` SQLite file holds disposable analysis for each source. CLI render requests remain a separate input. [Project examples](../README.md)
2. **Share the document model.** Both menus and the CLI read one edit into `CutProject`, validate it, and call the destination writer. The sequence model stores ordered source ranges and replacement-media provenance. The multicam model stores synchronized angles, group switches, audio routing and ordered assembly ranges. See the [wire format and examples](CUT-FORMAT.md).
3. **Report conversion losses.** A converter can require explicit loss approval for unsupported timeline material. Some host projects require this because the host's interchange export cannot describe every native effect. Each conversion writes a new destination. Host and structural limits can still prevent conversion after loss approval.
4. **Use the host where its native codec is required.** Resolve handles DRP/DRT. Premiere handles PRPROJ through its panel. Final Cut library conversion requires a person to complete the XML handoff in Final Cut. MPCut can convert FCPXML and FCPXMLD directly. See the [commands and file types](../README.md#convert-projects).

## Deferred collaboration protocol

Start with two local processes and a single explicitly linked timeline. Both peers read and save revisions to a separate session directory. Store a common baseline, media mappings and an append-only record of changes. Publish each revision atomically with a parent revision, origin ID, operation ID and checksum. Treat file notifications as a prompt to rescan. Recover missed notifications, duplicate deliveries and process restarts from the revision history.

For example, if MPCut moves clip B while the Resolve editor changes clip C’s microphone, merge both edits after checking that their resulting timings and downstream ripple ranges are compatible. If both change B’s in-point, surface both values and keep the last agreed revision until resolved. Check host identity, locks and current state immediately before applying a batch. Read it back before acknowledging it. Suppress echoes of already acknowledged operations while still recognizing a user’s subsequent Undo as a new edit.

Changes to editor-specific material require particular care. Rebuilding a timeline can discard grading or effects. Offer a separate named revision and retain the host original whenever an in-place operation cannot preserve that material. Show the active mode as live edits, receive-only, or revision exchange so the editor knows when to expect changes.

## Implementation order and acceptance

1. **Ship the shared document.** Define and validate the `.cut` schema for ordinary and multicam timelines and use it in the editor and CLI.
2. **Prove offline interchange.** Test native host fixtures and both forms of FCPXML. Exercise missing media, nested timelines, unknown features and loss reports.
3. **Add host-backed native import/export.** Start with DRP/DRT, then Premiere projects, then the Final Cut library workflow. Test each directional pairing of the four editors and distinguish unattended CLI conversion from an interactive host step. Promote each capability only after the destination reopens its native artifact and the recovered edit matches the report.
4. **Deferred follow-up.** Test open-project refresh, host edit APIs and collaboration per operation. Start with Resolve and MPCut, then Premiere. Require convergence in both directions, repeatable conflict handling, no duplicated edits after reconnect, and preservation of unrelated host work. Measure latency with realistic timelines before describing any mode as real-time. For Final Cut Pro, ship revision exchange first.

Use labeled camera frames and distinct audio tones to verify source frames, record positions, channel routing and rendered sound. Include fractional and drop-frame rates, nonzero source timecode, negative offsets, repeated ranges, silent spans, audio-only edits, nested multicams and two occurrences of the same source with different angle selections. Capture the actual timeline and angle viewer after reopening each supported native export.
