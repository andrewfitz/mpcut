# Sidecar storage locations

## Settings and behavior

Add a **Save new sidecars** picker in **Settings → Analysis**, next to the existing **Save and reuse analysis** toggle. The choice applies to all projects on this Mac, including projects already open. Each recording still has its own compressed SQLite sidecar.

| Setting | Destination for the next write |
| --- | --- |
| Next to media (default) | Keep the existing `Interview.mov.cutdb` beside `Interview.mov`. |
| In project folder | Use an MPCut-managed `MPCut Cache/` subfolder beside the saved project file. If the project is unsaved, keep new analysis in memory until the first project save. An explicit sidecar save offers to save the project first. |
| On cache disk | Use an MPCut-managed subfolder inside a directory chosen once in Settings. All projects use that directory, and projects referencing the same source can share its analysis. Remember the selected directory and volume identities. Verify both before reading, writing or clearing. If a different disk mounts at the same path, show the original as unavailable until the user chooses a replacement. |

Changing the picker affects future writes. Existing copies stay discoverable. Opening a project or inspecting a sidecar performs read-only discovery. When a selected disk is offline, full, or read-only, editing continues with available analysis. An explicit save reports the destination and the error. Reconnecting the disk enables subsequent saves. Save As updates the project destination after the project save succeeds.

## Finding the right sidecar

1. Introduce one location resolver in MPCutCore. Its inputs are the media URL, optional project URL, and a snapshot of storage preferences. Keep project context attached to jobs, including detached workers, so two open windows can use different project directories. Replace the single-path assumption in inspection, saves, exclusions, output conflict checks and receipts. [Current path and validation](../Sources/MPCutCore/AnalysisSidecar.swift)
2. Keep the legacy adjacent name. In managed folders use a sharded SHA-256 key so two folders containing `Interview.mov` have separate entries. Derive the project key from the normalized project-relative source path when possible. For the shared disk use a stable volume identifier and canonical volume-relative path when available, with the canonical absolute path as a fallback. Store the lookup identity in the manifest and check it on open. Keep media version checks separate so replacing a recording at the same path still goes through generation validation. Reuse the existing relink and media-evidence checks before associating a moved source with a prior cache.
3. Probe the adjacent file, project cache and configured cache disk regardless of the write setting. Register durable source-to-sidecar paths after successful saves or explicit folder scans. Keep discoveries made during normal reads in session memory. Inspection with empty preferences and no catalog creates zero files. It lets a file-only CLI command discover a known project copy and keeps old project or disk locations discoverable after changing folders. The catalog is a hint. Validate each candidate independently, deduplicate aliases, and probe deterministic paths even when the catalog is missing.
4. Among compatible copies, read the freshest committed data. Record last-content-change timestamps for the database and each logical analysis group in the same SQLite transaction as its changes. Rank copies by the timestamp for the requested group so a thumbnail write cannot make an older index appear newer. Reads, identical saves, and copying a database preserve that timestamp. Validate the source and relevant stream evidence first. Generation numbers are local to each database. A recorded metadata edit or clear takes precedence over an undated legacy value. Use filesystem modification time only among otherwise equivalent legacy candidates. Preserve the finer compatible waveform overview. Break ties with the selected destination, then a fixed location order. A newer database for stale media cannot displace a current one.
5. Resolve a complete analysis request against one consistent snapshot. For example, read all packet-index sections from one copy. If the freshest copy only has thumbnails, try the next compatible copy for the index. Track changes to independently editable metadata and record intentional clears so an older scene name or silence override cannot reappear. Read only small manifest and inventory records during discovery. Decompress the requested sections after selecting a candidate.

## Writing and clearing

- **Write to the selected destination.** On the first write after switching, seed a missing destination from the freshest compatible database using a consistent SQLite snapshot and atomic publication. If copies have diverged, reconcile complete compatible analysis groups, preserving unique sections, metadata edits and clears. Pin each active scan to the database where it acquired its lease. Exclude active leases from copies. Import only completed results or explicitly released checkpoints together with all their marker batches. Recheck destination state under the writer lock so simultaneous GUI and CLI saves preserve both updates. Copy stored compressed payloads directly where their checksums and source generation permit it. This work happens on demand for the recording being saved.
- **Add a Clear Caches… button.** Preview discovered sidecars and reclaimable bytes grouped by next-to-media, project folders and cache disks. Let the user clear one location or all known locations. Cover legacy adjacent sidecars as media are opened, with a folder picker for discovering older caches on demand. Identify disconnected locations and report skipped or busy files. List the directories cleared, bytes reclaimed, and each offline or busy location skipped. Explain that older copies skipped on a disconnected disk may become eligible again when it reconnects.
- **Preserve work during clearing.** Some sidecars contain scene names, manual silence thresholds, transcript results that may cost money to regenerate, and resumable work. Default to clearing rebuildable analysis. Retain the activity blobs referenced by transcript records, the corresponding scene report and markers for named views, stream evidence and any other dependency needed to reopen retained work. Preserve unknown section types. Offer explicit removal of whole sidecars with a preview of what else will be lost. Compact databases that retain records and report actual bytes reclaimed. Validate ownership and protected paths before deleting anything. Coordinate with active readers and writers, invalidate in-memory results that could republish cleared data, and update the catalog only after each successful clear.

## Delivery and verification

1. Build the core resolver, manifest migration and catalog. Keep format 3 and 4 readable. Cover same-name sources, symlinks, remounts, moved project trees, replaced media, duplicate caches, explicit clears, damaged payloads and offline roots.
2. Route single-source and multicam editors, CLI commands, live and file MCP operations, and background jobs through the resolver. Preserve the existing sidecar-disable controls. File-only CLI use in project-folder mode can read known copies and takes an explicit project context for writes. Include the actual read and write locations in inspection and save results. 3. Ship the picker, folder chooser and clearing flow together. Exercise all nine combinations of existing and selected location. Switch locations during a job, save from two projects at once, disconnect a disk during a save, and verify a failed save or clear leaves the prior committed data readable.
4. Race an active GUI scene scan with a CLI save after changing locations. Verify that only one lease can advance. Clear and relaunch with a paid recognition result, named scene, and unknown section, then reopen them without another provider call or scene scan. Touch a legacy database after an explicit metadata clear and verify the clear wins. Swap in a same-named cache disk and verify it receives no writes or deletions. Inspect with an empty catalog and confirm the directory tree is unchanged. Disconnect a disk during clearing, verify the completion report, then reconnect and verify its skipped copy is still discoverable.
5. Benchmark one-hour audio and video fixtures. Compare cold discovery, warm reopen, repeated saves, first write after switching, peak memory, and total bytes across all copies. Verify ordinary reads create zero files, decompress no unused payloads, and perform no recursive directory scans. Check that repeat saves leave unchanged compressed payloads intact.
