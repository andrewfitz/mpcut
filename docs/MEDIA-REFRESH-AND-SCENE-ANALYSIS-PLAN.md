# Resumable scene detection and project media refresh

**Proposed behavior.** Find Scenes uses what MPCut already knows, resumes unfinished work, and scans only when necessary. Refresh Project Media checks the recordings behind the timeline. It updates the index and visible previews, and tells the editor which analyses need attention.

## Find Scenes in the editor

| Situation | What the editor sees |
| --- | --- |
| One trimmed clip selected | **Find Scenes → Selected Clip** scans that occurrence’s source interval. For multicam, **Selected Camera** scans the selected recording. Disable the choice when there’s no eligible selection. |
| Whole project | **All Sources** scans each referenced video source once, including footage outside the trims. Multicam offers **All Cameras**. Audio-only sources contribute no work. |
| Current result | Show **Up to date** immediately. **Scan Again…** explicitly starts a replacement for the requested scope. |
| Partial result | Offer **Resume** and **Restart…**, with the saved position. Resume is the default. In a batch, resume matching partials and skip current sources without asking about each file. |
| Running | Show the source, elapsed media time, batch progress, and **Cancel**. A shot with no cuts still advances the bar. |
| Canceled | Show confirmed markers and the covered interval. Say **Paused · saved** only after the checkpoint commits. If only memory is available, say **Paused · this session only**. On a save failure, identify the last position that actually reached disk and offer retry. |
| Media changed | Label the affected result **Out of date**, explain what changed, and offer **Rescan**. If a refreshed recording is shorter than an edit or loses a selected track, show **Needs review** on the affected clip. |

Resolve the selection to stable clip/source IDs and half-open source intervals when the user starts the job. Moving the playhead or selecting another clip does not retarget it. Repeating a request for the same current result must decode zero frames. A scene spanning a trim remains one scene. A clip edge or checkpoint boundary must never manufacture a cut.

## 1. Store progress the detector can actually resume

The sequence editor already deduplicates repeated source IDs and skips completed reports. It currently weights every file equally. The native detector keeps recent sampled pictures, rolling motion, and a pending cut that the next picture may reject as a flash. The Swift collector matches each confirmed scene against recurring-view descriptors in encounter order. Cancellation currently unwinds before the final report is saved. [Scanner](../Sources/MediaProbe/scenes.c) · [Collector and report](../Sources/MPCutCore/Scenes.swift) · [Sequence integration](../Sources/MPCutApp/EditorModel.swift)

- Separate **source generation**, **scan attempt**, and **coverage**. A checkpoint records the stream, verified clock, detector version and settings, scope, and attempt. Track the decoded position separately from the last confirmed boundary and the last durable checkpoint. Keep an unfinished final scene open. Only real end-of-stream may flush the detector’s pending last frame as a source-ending decision.
- Store the small sampled-frame history, presentation timestamps and frame ordinal, motion values, pending candidate, and recurring-view descriptors needed to continue. Seek to an earlier verified random-access point, preroll the decoder, match the saved resume position, then advance the restored detector exactly once per new frame. Include enough sequence information to disambiguate repeated timestamps. If the seek, clock, or decoder path cannot be reconciled, discard that attempt’s incompatible suffix and restart from a verified point. Never splice two decoder attempts merely because their timestamps look alike.
- **A selected range can finish without scanning hours of preceding footage.** First slice a current full-source report if available. Otherwise start a range-local attempt, seek before its start for decoder context, and read the lookahead needed at the end. Record the initialization context. Range-local results satisfy that scope; a later whole-source run may adopt them only if its incoming detector and view state matches at the boundary. Otherwise rescan that interval. Never promote a collection of disjoint completed trims to a whole-source report by adding their durations. Keep range-local view IDs scoped to their report. Transfer a user’s view name only when the view identity is verified.
- Save incremental marker batches and checkpoint state in one SQLite transaction. Start with a periodic flush at most once every five seconds of wall time, plus pause and completion flushes. Tune against long-file measurements. Never rewrite the full index or marker history per batch. Stopping decoding and flushing a checkpoint need separate cancellation lifetimes. A graceful cancel finishes the bounded flush; a hard kill leaves the last committed checkpoint. Surface write failures explicitly. The current best-effort autosave helper discards them. [Sidecar writer](../Sources/MPCutCore/AnalysisSidecar.swift)

## 2. Make repeated requests and concurrent writers predictable

Use one core planner for sequence, multicam, CLI file scans, saved projects, and MCP. Use the verified stream inputs, detector revision and compatible scope/context to decide reuse. Deduplicate aliases that resolve to the same recording. Snapshot the batch denominator as the union of requested source durations, counting repeated references once. Show cached coverage immediately, throttle visible updates, and keep the bar below completion until the result is published. Where duration is unknown, show elapsed media time until the clock is verified.

Within a process, subscribe to compatible running work. Canceling one subscriber releases its interest. Other subscribers keep their work. Across processes, claim the attempt in the database and let other callers read the committed progress. Use a renewable claim with an owner token and a monotonically increasing fence. Every batch and final commit must still own that fence and match the current source generation. After an abandoned claim is taken over, a delayed former writer cannot publish. Readers of the cache never need a long-held write lock.

**Restart** creates a replacement attempt for that scope. Keep the last good completed report readable if its inputs are still current. Publish the new report, its coverage, and its active-generation pointer atomically. A failed or canceled restart leaves the previous report and the new checkpoint distinguishable. If both exist, a normal lookup returns the current completed report; an explicit Resume continues the replacement. A retry of the same restart operation ID must return the original attempt. An intentional second restart uses a new ID.

## 3. Refresh the project without invalidating unrelated work

Ship **File → Refresh Project Media** first. Add **Automatically refresh changed media** as an opt-in setting. Both use the same refresh operation. With automatic refresh enabled, watch the parent directories of open media, coalesce replacement/rename events, ignore sidecar writes, and recheck on activation or remount. Defer growing or partially replaced files until stable. With it disabled, retain the existing identity checks before edits and exports. A manual refresh always works independently of the watcher and of sidecar persistence.

The current sidecar checks a file stamp, tolerates a changed device number on remount, and binds each section checksum to the saved stamp. Its first write after a stamp mismatch deletes all sections. A source refresh cannot safely retain sections by updating that stamp in place. [Identity checks and storage](../Sources/MPCutCore/AnalysisSidecar.swift) · [Analysis sections](../Sources/MPCutCore/SidecarAnalysis.swift)

For a normal check, stat each unique file once and stop when unchanged. Treat a watcher’s content-change event as a reason to verify even if the stamp is unchanged. Offer an explicit deep verification for a suspected same-size, same-timestamp replacement. During a necessary index pass, collect per-stream digests of the encoded payload, framing, codec configuration, and presentation timing, including edit lists and the mapping to source time. Avoid a second whole-file read to certify reuse. If an existing index path skips payloads or the old sidecar has no comparable evidence, mark the affected analysis stale. Save the initial fingerprint during the first eligible indexing pass so the next refresh has a baseline. For a confirmed same-stamp replacement, allocate a new generation even though its file stamp matches. A matching filename, duration, or codec is insufficient. Ambiguous track matches require review.

| Verified change | Automatic work | User-triggered analysis |
| --- | --- | --- |
| Audio replaced on one track | Reindex the file as needed for packet offsets and export checks. Replace the affected playback reader and request visible waveform tiles for that track. | Invalidate that track’s silence and measured room tone. Preserve scenes and other tracks’ results when their inputs and clocks match. |
| Video content changed | Reindex and regenerate visible thumbnails first. Drop old decoder frames and thumbnail requests. | Mark scenes stale. Preserve silence for verified unchanged audio tracks and timing. |
| Container, orientation, or timing metadata changed | Refresh container-dependent export decisions. Rebuild display tiles if their transform changed. Verify or rebuild all byte-offset indexes after a remux. | Preserve only analyses whose own inputs match. A container edit that shifts source time can invalidate markers even when packet payloads match. |
| Threshold, audio route, or edit changed in the project | Reuse source indexes and matching waveforms. Rebuild the affected timeline projection or multicam program pause map. | Key silence by stream and analysis settings. Preserve unrelated tracks, scenes, and the user’s manual threshold separately from measured calibration. |
| Offline, shortened, or missing referenced tracks | Keep clip IDs, trims, marks, routing, history, and user labels. Disable only operations that need the missing or incompatible media. Offer relink/review. | Identify the old report by generation. Stale data may be inspected explicitly. Snapping, pause removal, and scene-based export require verified coverage. |

Validate all references before swapping in the replacement, including repeated occurrences, audio replacements, undo/redo entries, and queued export snapshots. Never move a cut or substitute a track by ordinal to make a replacement fit. Pin active exports to their validated source generation or fail with a source-changed error before publishing output. Publish refreshed state per source, discard callbacks from superseded readers, and ask only for visible preview tiles plus the existing small lookahead. Preserve project edit history during a refresh. Keep scene and silence jobs out of the preview-refresh queue: loading a waveform for playback must not implicitly launch either scan. Recheck the file identity immediately before publishing the refreshed index; if the source changed again, discard the staged result and coalesce another refresh.

## 4. Migrate the adjacent database and expose one contract

- **Storage.** Add a versioned manifest for source generations, per-stream evidence, active reports, attempts, and coverage. Distinguish immutable analysis blobs from the generation that has verified their dependencies. Verify old checksums against the old stamp before referencing or copying a payload into a new generation. Migrate a recognized v1 database transactionally on first writable use. Current `scenes.v2` reports can satisfy a full-source request for the same verified file. Read-only inspection must not migrate or create anything. Preserve unknown/newer databases, the existing collision and symlink protections, and rollback-journal compatibility. Old clients must refuse the new schema without overwriting it. Reclaim superseded attempts and unreferenced payloads only after readers and writers release them.
- **Live GUI and MCP.** Extend `scan_analysis` with optional scope and reuse/resume/restart policy; retain the existing all-project default and revision/operation-ID checks. Extend `analysis_job_status` with requested, confirmed, and durable coverage. Keep job lifecycle separate from artifact validity: a canceled job can leave a resumable analysis; a failed refresh can leave a previous report available for inspection. Report in-memory and persisted cache status separately when they differ. Expose project refresh through the same live-job mechanism. [Current MCP schema](../Sources/MPCutApp/MCPResources/analysis.json)
- **CLI and file MCP.** Keep the existing `mpcut scenes FILE` invocation, complete-report JSON and `file_scenes` behavior. Add explicit file ranges, saved-project clip IDs or all-source scope, and restart intent. Propagate these through the file MCP wrapper. Expose the same status and stale reasons through `sidecar --status` and `file_sidecar`. A project refresh from the CLI checks the saved project’s sources without rewriting the project. Send progress to stderr or a requested event stream. Keep stdout parseable. Ctrl-C returns a canceled outcome and reports the last durable coverage.
- **Persistence policy.** With sidecars disabled, keep new work in session memory and bypass automatic reads and writes. Explicit Save Analysis Sidecars may persist available checkpoints. A read-only directory or disk-full error must not prevent editing. Never promise cross-launch resume when the checkpoint could not be saved. On read-only or unsupported storage, deduplicate within the process; do not promise a cross-process worker claim.

## Delivery and acceptance

| Deliver in order | Acceptance check |
| --- | --- |
| 1. Core checkpoint, storage migration and full-source resume | Compare boundaries, final scene ends, view membership and labels against an uninterrupted scan across flashes, variable frame rate, reordered frames, long GOPs, reader fallback and cancellation just before EOF. Kill between SQLite writes, reopen, and verify there are no missing or duplicate markers. |
| 2. Selected/all scopes and GUI, CLI, MCP integration | Start in the GUI, cancel, resume in the CLI, then read the identical completed result over MCP. Scan a late trim from a cold cache without decoding the whole prefix on seekable media. Test overlapping requests, cancellation by one subscriber, and two processes taking over the same claim. On a single-shot fixture, progress must advance before EOF although no new markers arrive. After releasing the last subscriber, verify that persistence failure reports the previous durable position. |
| 3. Manual refresh and selective invalidation | Replace only the soundtrack, remux unchanged streams, swap track order, preserve a timestamp while changing bytes, and shorten a source past an edit. Assert exactly which inputs were reindexed, which reports survived, which went stale, and that old callbacks/exports cannot publish as current. |
| 4. Automatic refresh and performance | Exercise atomic replacements, network remounts, repeated change events and sidecar opt-out. On a two-hour source, measure frames decoded, bytes read/written, main-thread updates, cancellation latency, and first refreshed visible tile. Warm repeats must decode zero frames; a seekable resume should read only preroll and the unfinished span. |
