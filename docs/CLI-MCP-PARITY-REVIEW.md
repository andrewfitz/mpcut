# CLI and MCP feature gaps for review

Reviewed November 24, 2026 against `2b8198a` and the uncommitted working tree. **The checkout now exposes 293 MCP tools, including 112 in files-only mode.** The Tiles family accounts for 31 live tools and 30 file tools. In a running editor, a Tiles layout edit changed the very next review frame, Undo restored the previous picture, and the saved project stayed untouched. The most consequential remaining gaps are project output settings, completing a reviewed batch of dialogue switches, and carrying pending GUI review decisions into automation.

## Highest-impact gaps

| Surface | Missing capability | Evidence and impact |
| --- | --- | --- |
| CLI, file and live MCP | **Edit persistent project output settings.** | File → Export Settings changes the project canvas size, frame rate, background, soundtrack route and unchecked-coverage policy. The GUI uses dedicated core setters, including special handling for still timelines. The command and tool catalogs have no equivalent general settings edit. ISO delivery flags, still-project creation, soundtrack attachment and multicam audio routing cover individual cases. An agent editing an existing project cannot reproduce the whole output setup. [GUI](../Sources/MPCutApp/ProjectOutputSettings.swift) · [Core setters](../Sources/MPCutCore/ProjectOutputSettings.swift) · [CLI catalog](../Sources/MPCutCLI/CommandPath.swift) |
| CLI and file MCP | **Commit a reviewed set of dialogue switches.** | On a three-turn transcript the CLI returned two proposals from one revision. Applying the first succeeded. Applying both in one ordered request failed with `stale_tile_switch` on the second and published no file. Each operation validates the original revision against the already-edited project. File MCP fails earlier: `project_file_edit` rejects the CLI’s `project_revision` property, and there is no `tiles_file_switches_accept`. An unguarded `switch_set` can write a cut but loses the reviewed-revision check. The CLI JSON help for `project edit` also omits this optional revision field. [CLI authoring](../Sources/MPCutCLI/ProjectAuthoring.swift) · [Revision check](../Sources/MPCutCore/TileSwitches.swift) · [File schema](../Sources/MPCutApp/MCPResources/file.json) |

Automated acceptance reads the scan and count hints. It does not apply the GUI’s saved review choices. The edit tools can reconstruct many choices after acceptance, but a person cannot hand that pending review to an agent and get the same result in one native edit. [GUI acceptance](../Sources/MPCutApp/ParticipantInspector.swift) · [Saved review choices](../Sources/MPCutApp/TilesPendingReview.swift) · [MCP acceptance](../Sources/MPCutApp/MCPTiles.swift) · [CLI acceptance](../Sources/MPCutCLI/TilesReviewCommands.swift) |

The CLI rejected `offset` on a generated multicam project. Live MCP exposes these controls. [CLI actions](../Sources/MPCutCLI/ProjectAuthoring.swift) · [Live actions](../Sources/MPCutApp/MulticamMCP.swift) |
| CLI, file and live MCP | **Persist a transcript voice’s explicit camera assignment.** | The GUI’s **Link Transcript Voices** writes or clears a project-level speaker-to-angle link. Proposal requests accept temporary `voice_angle` overrides and return the resulting suggestions. Feed voice bindings are separately editable. The persistent direct voice-to-camera assignment has no corresponding command or MCP edit. ## Live editor controls and retry behavior

- **Project History can be opened and then blocks saving.** The history sheet has a native Cancel button. MCP can show it and read its visibility, but has no close action. A packaged-editor check returned `history_visible: true` followed by `busy` on `project_save`. Notice dismissal targets editor messages. [Lifecycle](../Sources/MPCutApp/MCPLifecycle.swift) · [Modal state](../Sources/MPCutApp/ProjectSessions.swift) · [History sheet](../Sources/MPCutApp/ProjectHistoryView.swift)
- **Starting a still-only timeline in a blank live window still requires the GUI.** Native first-image import opens the format chooser. Live still insertion requires an editable picture timeline, and remote media import bypasses the first-image branch. CLI and file MCP can create the project and live MCP can subsequently open it. Still soundtrack attach, fit and detach now exist on all three surfaces. [Live guards](../Sources/MPCutApp/MCPStills.swift) · [Native image import](../Sources/MPCutApp/EditorModel.swift) · [CLI paths](../Sources/MPCutCLI/CommandPath.swift)
- **Some visible controls remain unreachable.** These include switching the actual Tiles monitor between Source and Output, showing or hiding cut sections, full-height panel docking, transcript Follow Playback and its remembered suggested camera, and listing or clearing Open Recent. Explicit source/output frame review and showing the Tiles panel already work. [Monitor](../Sources/MPCutApp/ParticipantMonitor.swift) · [Timeline](../Sources/MPCutApp/Timeline.swift) · [Docking](../Sources/MPCutApp/EditorWorkspace.swift) · [Reader](../Sources/MPCutApp/TranscriptPane.swift) · [Recent files](../Sources/MPCutApp/RecentFiles.swift) · [Layout schema](../Sources/MPCutApp/MCPResources/presentation.json)
- **Live Tiles calls lack the existing MCP retry receipt.** None of the 31 live Tiles schemas accepts `operation_id`. The live bridge only caches and replays an outcome when that field is present. Revision checks protect committed edits, but a client that loses the reply cannot retry for the original outcome or job ID using the same key. File Tiles jobs already accept an operation ID. [Tiles schemas](../Sources/MPCutApp/MCPResources/tiles.json) · [Bridge replay handling](../Sources/MPCutApp/MCPLocalControl.swift)

## Verification

The search covered the desktop menus, inspectors, modal workflows and settings, CLI dispatch and request parsers, all MCP schema families and their handlers, and the generated tool reference. It included project lifecycle, sequence and multicam editing, history, media maintenance, Tiles, stills, playback and layout, analysis, transcripts, review frames, queues, export and interchange. The GUI inventory identified 742 literal control labels across 48 files. Dynamic controls and commands were also checked directly. The findings describe public entry points. Runtime checks targeted the specific boundaries below.

- Built the current tests with `swift build --build-tests`. Ran the Tiles, review-frame and feed-angle conversion editor suites muted on Backstage. All 15 tests passed. [Tiles tests](../Tests/MPCutAppTests/MCPTilesTests.swift) · [Frame tests](../Tests/MPCutAppTests/MCPReviewFrameTests.swift) · [Angle conversion](../Tests/MPCutAppTests/FeedAngleConversionTests.swift)
- Ran three CLI integration cases against generated media. Manual feed authoring, arranged swaps and blanks, and a rendered ISO → transcript proposal → saved switch all passed. Also exercised a two-proposal batch, camera-offset update, multicam pause protection and lossless PNG extraction separately. [CLI fixture](../Tests/Integration/tiles_e2e.py)
- Ran the packaged-protocol fixture on Backstage against the current debug app and the separate Feeds release as described above. Queried `tools/list` in both modes for every listed artifact, compared the current helper’s complete input schemas to source, and exercised both file-MCP schema rejections. The generated MCP reference passes `python3 scripts/mcp-reference.py --check`. [Live fixture](../Tests/Integration/tiles_editor_mcp.py) · [Reference check](../scripts/mcp-reference.py)
