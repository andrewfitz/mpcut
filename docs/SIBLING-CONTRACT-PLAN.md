# MPCut changes for the shared contract

Proposed · 25 November 2026

MPCut, ColorGrade and MonitorKit are separate products that share one command grammar, one JSON spelling, one set of exit statuses and the data they pass to each other. The [shared contract](../../../ultracam/docs/shared/SIBLING_CONTRACT.md) states that target with one form for every rule. ColorGrade and MonitorKit are built to it from the start. This page lists what MPCut changes to reach it. [Naming convention](NAMING-CONVENTION.md) · [ColorGrade plan](../../../ultracam/docs/COLORGRADEKIT_PLAN.md) · [MonitorKit CLI plan](../../../ultracam/docs/monitorkit/HEADLESS_CLI_PLAN.md)

MPCut's design was the starting point for the contract, and most of it carries over unchanged. Where MPCut had two names for one thing, or a shape that did not suit three products, the contract picks the better form and MPCut moves to it. The [naming convention](NAMING-CONVENTION.md#adoption-across-the-app) already sets the method: ship one current contract across the app, CLI, MCP helper, plugins and saved formats, and remove retired names and fallback readers in the same release. All three products are in development, so nothing keeps backwards compatibility. Each change below is made in place. There are no aliases, no readers for the earlier form, no converters and no migration of saved projects.

Nothing here has been implemented. No MPCut source, descriptor or guide was edited. Each statement about current behavior was checked on 25 November 2026 against the working tree at commit `331bb63`, by reading source or by running the built CLI. The tree had uncommitted changes from other work at the time, so line numbers may have moved. A row that was inferred and not read or run says so.

## Changes to existing behavior

Each row replaces the left column with the right column. The left column stops working.

| Area | Now | Target | Why |
| --- | --- | --- | --- |
| Times in CLI results | `{"numerator": 37, "denominator": 25}` objects. Live MCP tools already write `"37/25"`. | The string, everywhere a time is written. | The string is the form flags and `project edit` accept. Replayed scan reports, and any request that sends the object form, are the exception today, as the row on time objects in requests says. They move to strings with the results. A result can then be passed straight back in, to MPCut or to a sibling. |
| Times inside a `.cut` | The timeline stores strings. `media_snapshot` and `transcripts` store objects. | Strings throughout, as project schema 10. MPCut opens only schema 10, as it opens only schema 9 now. A schema 9 project is recreated. | One time format in the saved document. |
| Result header | Command results carry `ok`. `--version` and `help` do not. Nothing names the product or command. | Every JSON result MPCut prints, and every manifest or report saved from one, begins with `ok`, `product: "mpcut"` and `command`. A command reading a request ignores those three members, so a replayed report still works as input. Projects, schemas and requests have no header. | A saved result tells the next product what it is. |
| Written files | A render returns `output` as a path string. A still render adds `output_bytes`. | `output` is a file descriptor: `{path, media_type, byte_length, sha256}`. A batch returns `outputs` as a list of them. `output_bytes` is retired. | Every product reports a written file the same way, with a digest that binds later work to the exact bytes. |
| Frame size | `--preset full` writes display resolution, so a source with non-square pixels is de-squeezed. | The stored pixels after orientation, with no scaling, and `pixel_aspect_ratio` on the row. | A region drawn on an exported frame registers with the source. |
| Frames manifest | Six writers produce three version 2 shapes: single source, program and multicam angles, across the CLI, the still review and the MCP review tools. Rows name the written image `file`. | One version 3 shape with a `clock`, `preset` and `format`. Every row has `id`, `request_number`, `requested_time` and `availability`. A row with a picture has `output`, `width`, `height`, `resampled`, `has_alpha`, `stage` and `signal`. Its `frame_time` is where the picture starts on the manifest clock. On the sequence, group and assembly clocks, `source_frames[]` names each recording shown and that frame's own time: one entry for an angle, several for a composite, none for a generated gap. A held still on the source clock has `still: true` and no `frame_time`. Multicam `group_time` becomes `requested_time` on the `group` clock. `generated_gap` becomes an availability. [Shared schema](../../../ultracam/docs/shared/frames_manifest.schema.json) · [Multicam example](../../../ultracam/docs/shared/examples/mpcut.frames_manifest.json) | One reader in MonitorKit and ColorGrade handles every manifest. `file` keeps one meaning, the source media. |
| Exit statuses | 1 for every failed operation. | 4 for a failed check such as `tiles angles verify`. 5 for a capability this Mac lacks. 6 for `missing_source` and `source_changed`. 7 for `stale_render_plan`, `stale_tile_review`, `stale_tile_switch`, `project_save_conflict`, `project_closed` and `output_exists`. The [shared code table](../../../ultracam/docs/shared/codes.json) gives the status of every shared code, and `control_disabled` folds into `app_unavailable`. 0, 1, 2, 3 and 130 keep their meaning. | A script can tell a missing file from a conflict from a failed check without parsing text. |
| Missing source file | `media inspect` on a missing movie returns `invalid_input`. A missing still returns `still_offline`. A missing project given to `project edit` returns `cut_project_read_failed` with exit 1. | `missing_source`, exit 6, decided before any format-specific decoding. A file that is present and unusable is `invalid_media`, as the row on unusable media says. | One code for one condition across the three products. |
| Reused operation ID | File jobs return `operation_id_conflict`. Live tools return `operation_conflict`. Transcript jobs return `transcript_operation_conflict`. | `operation_id_conflict` for all three. | One name. |
| Receipt replay | A live replay after its window closed is refused, unless the call was `project_close`. A file job compares a digest of the arguments as they were sent, so `"10"` and `"300/30"` conflict. | The receipt is looked up before any check of current state, so an exact retry returns it after a close or a later edit. Arguments are compared after defaults, absolute paths and reduced times are applied. The helper's `cli_capabilities_read` reports `receipt_retention_seconds`. | A retry is safe whenever the first call might have landed. |
| Saved-file guard | Live tools take `expected_revision`. Saved-file `project edit` takes `project_revision`, a SHA-256 of the project model, for a reviewed tile-switch batch. | `project inspect` returns `revision` for a saved file, binding a counter to the SHA-256 of the saved bytes. Every saved-file mutation takes it as `expected_revision`. `project_revision` is retired. | One guard name on a window and on a file, and every saved-file edit can be guarded. |
| Clock selector | `timeline range map` and transcript commands use `--space`. Review commands use `--clock`. | `--clock`, and `clock` in JSON. | One name. |
| Output directory | `scenes export` uses `--export-to`. | `--output`. | One name. |
| Enum flag values | Some are kebab-case and some snake_case: `every-frame`, `keep-offline`, `source-timecode`, `non-silent`, `cpu-only`, `422-hq` beside `separate_tracks` and `current_cut`. | snake_case, identical to the JSON value. | A value copies between a flag and a request unchanged. |
| One-based fields | `error.segment` and `failed_range` count from one without saying so. | `error.segment_number` and `failed_range_number`. | `_number` is one-based and `_index` is zero-based, everywhere. |
| `media inspect` detail | The CLI uses `--frames`, `--keyframes` and `--audio-packets`. The MCP tool uses `detail`. | `--detail metadata\|frames\|keyframes\|audio_packets` on the CLI as well. | A command and its tool take the same options. |
| `media inspect` streams | `sample_rate`. Times as objects. No shared description of color. One stream type serves audio and video, so an audio stream reports `width: 0`, `height: 0`, `bit_depth: 0`, `pixel_format: "unknown"` and a zero `frame_rate`. Frame rows carry `can_start` and `can_end`, and audio packet rows name their stream `stream`. | `sample_rate_hz`. Time strings. A shared `signal` on each video stream and on `image`, beside the existing `color_*` strings. A member that does not apply to a stream's kind is omitted. The result names its `detail`, and audio packet rows use `audio_stream_index`. [Shared schema](../../../ultracam/docs/shared/media_inspect.schema.json) | Values carry their unit, and all three products return the same members. |
| MCP protocol | The helper serves 2026-07-28 and four earlier revisions, back to 2024-11-05. | 2026-07-28 and later. A host on an earlier revision is refused. The handshake code for the earlier revisions is removed, and their tests stay as refusal tests: a host that offers only an earlier revision must be turned away. | 2026-07-28 differs enough from the earlier designs that carrying both is not worth it, and current hosts support it. One floor across the three helpers. |
| `project media relink` | `--from` and `--to` take paths. | `--source OLD --with NEW`, as `project media replace` already does. | `--from` and `--to` always take times. |
| `project convert` | `--to cut\|resolve\|premiere\|fcp` names the format. | `--format`. | `--to` always takes a time, and `--format` names the format of a written file. |
| `project media replace` alignment | `--clock source-relative\|source-timecode` chooses how the new file lines up. | `--align source_relative\|source_timecode`. | `--clock` names one of the four shared clocks. |
| `project media replace` identities | `--source` and `--with` are paths. The candidate is previewed as it is on disk and rechecked at publication, so a file swapped before the preview passes. | In a request, `source` and `with` are source identities with an optional `sha256` and `byte_length`. Both digests are checked at preview and at commit, and a mismatch is `source_changed`. | A ColorGrade render's `source` and `output` pass straight in, and the edit takes exactly the bytes that were graded. |
| Review tool fields | `review_editor_frame_read` takes `time`, `space` and `view`. | `at`, `clock` and `stage`. `view: output\|source` becomes `stage`, the shared word for where a picture is taken. | One name for a time, a clock and a stage across the three products. |
| `space` and `time` on the other live tools | About forty tools take `space`, counting nested arguments, among them the `timeline_*` tools, `playback_transport_control`, `review_editor_frames_export`, the still tools, `multicam_assembly_edit` and the `transcript_editor_*` tools. Transcript `space` also accepts `current_cut`. | `clock` everywhere, and `at` for a single time. `current_cut` is a transcript scope and moves to its own `scope` argument, since it is not one of the four clocks. | `clock` names one of four clocks in every tool. |
| Time objects in requests | The shared time decoder accepts `{numerator, denominator}` as well as a string, so a request may still send an object, and the replayed scene and silence reports do. The review audit also found tool arguments declared as objects, which was not re-checked here. | Strings only, in every request and report. | One time form in and out. |
| Render tool arguments | The editor render tools take `codec` and `audio_track_ordinal`. Stream flags vary across commands: `--audio-stream`, `--stream`, `--replace-track`, `--replacement-stream` and `--reference-stream`. Manifest angles use `video_stream`. | `video`, as the CLI flag is named. `video_stream_index` and `audio_stream_index` everywhere a stream is chosen, with a role prefix where a command has two, as in `replacement_audio_stream_index`. Ordinals are removed. | A stream is always a zero-based absolute index. |
| Job families | Transcript jobs have their own commands and states, among them `preparing`, `completed`, `partial`, `interrupted` and `stale`. `analysis_job_*` and `export_editor_job_*` are further families. | One `job` family. A transcript job ends as `succeeded`, `failed`, `cancelled` or `needs_review`, and `partial`, `interrupted` and `stale` become reasons on those states. | One way to poll, cancel and read any job. |
| Saved-file `project edit` | The request has no `in_place` and no `expected_revision`. | `in_place` or `out_project`, and `expected_revision`, as the live tool has. | The balance handoff ends in `project edit --in-place`, and every saved-file edit can be guarded. |
| `project media` commands | The project is a positional argument. The six commands take flags only, with no `--input` or `--stdin`, and a preview exists only in the MCP tools. | `--project` for the project, `--input` and `--stdin` for a request with `source`, `with` and `out_project` or `in_place`, and `--dry-run` as the preview. It reports what the commit will verify and returns a `plan_token`, and the commit takes `--plan-token`. | The render-to-replace handoff runs from a request file, and a CLI caller can preview. |
| History comparison result | `history compare` returns `changes`, the timeline items that differ, and `project_fields`. | `project_fields` becomes `changed_fields`, an array of dotted field IDs, as ColorGrade returns. `changes` stays as MPCut's own member. | Both apps name changed authored fields the same way. |
| Unusable media | A file that is present and cannot be read returns `invalid_input`. | `invalid_media`, exit 1, as MonitorKit reports it. `invalid_input` stays for a request value that is not media. | One code for one condition. |
| Occupied output | An occupied destination is `output_exists`, and no CLI option overrides it. | `--replace`, `replace_existing` in a request, publishes over it. The default is unchanged. | A repeated run can keep its destination. |
| Media-level `origin` | `media inspect` and the frame manifests report the media's start as `origin`. | `start`, the name every stream already uses. | `origin` means who made a history step, and in MonitorKit where an exported picture came from. |
| Frame and packet rows | `media inspect` frame rows carry `dts`, `can_start` and `can_end`, and `frame_rate` and `time_base` are objects. A video stream carries zeroed audio members, and `frames: []` appears at metadata detail. | Strings for `frame_rate` and `time_base`. `dts`, `can_start` and `can_end` stay as MPCut's own row members. | Working directory in tools | About a hundred tools take a `working_directory` argument. | Removed. MCP callers send absolute paths. | One path rule. |

| `media inspect` selectors | The CLI takes `--stream` and `--audio-stream`. | Frame at the end of a program | A program frame requested exactly at the end of the timeline returns the last picture. | `no_frame`, as `containing` defines it. `--frame-match at_or_before` returns the last picture. | One rule at a boundary in all three products. |
| `--input` with flags | `project create`, `project edit`, participants and Tiles commands reject any other flag beside `--input` or `--stdin`. | A flag may repeat a request value when the two agree. A disagreement is `invalid_arguments` with a pointer. | The contract's one rule for a request plus flags. |

Stdin and flags keep the working directory. | A request file can move with the files it names. |

## Additions

| Addition | Detail |
| --- | --- |
| `capabilities` | `mpcut capabilities --json` and `cli_capabilities_read`. Readable and writable formats, encoders, `limits` and the `detector_capabilities` now in `--version`, with a reason for each unavailable feature. |
| `help schema NAME` | Print one published JSON Schema, starting with the project schemas in `docs/schema`, the frames manifest and the media inspection result. |
| `--version` members | The shared version result: the header, `version`, `build_id`, `shared_contract_version: 1` and `schema_versions`, an object such as `{"project": 10, "frames_manifest": 3}`. `project_schema_versions` and `detector_capabilities` leave `--version`. |
| `job` command paths | `job list`, `job status`, `job result`, `job cancel` and `job release` on the CLI, and `file_job_list` in the helper, over the existing receipts. |
| `error.pointer` | The RFC 6901 JSON Pointer to the request field at fault. |
| `--frame-match` | `containing` stays the default. Add `exact`, `at_or_before`, `at_or_after` and `nearest` to `review frames export` and the frame-read tools. The shared contract's table fixes each rule at a boundary, in a gap and past the end. |
| Dry-run render result | A dry run returns `planned_output`, with `path` and `media_type`, and `plan_token`. It has no file yet, so it reports no `output`, length or digest. The real run returns `output`. |
| `--progress` everywhere | On `export project render` and every other command that can run long. It is on scans, refresh, transcript, participants and tiles commands today. |
| `--project-handle` | Let the CLI address an open window through the local control socket, as the live MCP tools do. |
| `--stage` on `review frames export` | With a project, `output` is the default and `source` exports the untreated recording. The manifest already reports `stage`. |
| `--base-dir`, `--allow-outside-base` | The base for relative paths in a request. A frames manifest MPCut reads from another program may name files only inside its own directory, or the command fails with `path_outside_base`. |
| `capabilities.limits` | The bounds MPCut enforces, by name. A request over one fails with `limit_exceeded`. |
| Progress records | `--progress jsonl` writes the shared progress record, one per line on stderr. |
| PNG and TIFF for rendered Tiles frames | These are JPEG only today, which rules them out for measurement. |

## What the change touches inside MPCut

- **Integration tests.** Forty-five files under `Tests/Integration` read `numerator` and `denominator` from results. Tests that assert exit status 1, `output` as a string, or the version 2 manifest fields change with them.
- **Saved projects and reports.** Schema 10 for `media_snapshot` and `transcripts` times, with new golden files. Test projects and fixtures at schema 9 are regenerated. A silence or scene report written before the change is produced again by a new scan.
- **Descriptors and generated reference.** The JSON in `Sources/MPCutApp/MCPResources`, [MCP reference](MCP-REFERENCE.md), `help --json` and the three offline guides.
- **Guides.** [CLI guide](CLI.md), [Headless guide](HEADLESS.md), [Agent guide](MCP-AGENT-GUIDE.md), [MCP coverage](MCP-COVERAGE.md), [Project format](CUT-FORMAT.md) and [Usage](USAGE.md). The agent guide and the coverage page describe a host negotiating MCP revision 2025-06-18 and helper tests on four earlier revisions. Those passages become a statement that only 2026-07-28 and later are accepted.
- **Plugins and the walkthrough.** The skill instructions under `plugins/mpcut` and `docs/mcp_walkthrough.py` name tools, fields and error codes.
- **File worker.** The mapping from a child's exit status to a job state in [the file job runner](../Sources/MPCutApp/MCPFileJobs.swift) gains statuses 4 through 7.
- **Naming convention.** The line that says to specify an index base goes, since `_index` is always zero-based.
- **Go helper.** Error messages and the `app_unavailable` text in [the bridge](../mcp/bridge.go), and the multi-revision cases in [the SDK tests](../mcp/main_test.go) and the file worker test, which become refusal tests.

## Corrections that stand on their own

- **Settings path.** [MCP plan](MCP-PLAN.md) still places Enable local MCP control under Settings → General → Automation. The Settings window has an Automation page, and the control is there. The naming convention, the agent guide, the usage guide and the bridge's `app_unavailable` message already say Settings → Automation.
- **`project merge` exit status.** [CLI guide](CLI.md#convert-and-hand-off-projects) says it exits 1 for a conflict. The code exits 2: `merge_conflict` and `merge_invalid` are thrown as `CLIError`, and the top-level handler maps every `CLIError` that is not a request code to 2. This was read from [the entry point](../Sources/MPCutCLI/main.swift) and not run. Make the guide true: exit 1 for `merge_conflict` and `merge_invalid`, which leave marked text in the file for a person to resolve, and a status above 128 for `merge_failed`, which Git treats as a failed merge and not as a conflict. Test the status, the code and the contents of the file together. As a Git merge driver it stays outside the shared exit table.

## Shared code

The three products must write a time, a result header, an error object, a file descriptor and a signal the same way, and must map container tags to a signal through one table. Three separate implementations would drift. So these go first, into one small Swift package with no dependencies that builds for macOS and iOS, because MonitorKit's libraries must stay dependency-free and build for iOS. MPCut's `RationalTime` and error encoding are the starting code. The package is tested against the shared schemas and fixtures.

The [ColorGrade parity specification](../../../ultracam/docs/colorgradekit/MPCUT_PARITY.md#how-to-share-the-implementation) also proposes sharing the Go MCP transport, the exact-byte save guard, history retention and the cache cleaner. Extract each of those, with its tests, when its second consumer is being built. MonitorKit's files-only helper uses the same Go transport.

## Order of work

1. Correct the settings path in the MCP plan and fix the `project merge` status.
2. Build the shared Swift package: time string, result header, error object, file descriptor, signal and the tag-to-signal table.
3. On a branch, make every row of the table of changes above. Nothing in that table is optional, and the rows depend on each other: times, the header, descriptors and the manifest change together.
4. Add everything in the table of additions.
5. Update descriptors, guides, plugins, the walkthrough and the integration tests in the same branch.
6. Merge when three things pass: MPCut's own tests, the contract check, and the discovery check against the built bundle. [Discovery check](../../../ultracam/docs/colorgradekit/check_mpcut_parity.py) · [Contract check](../../../ultracam/docs/shared/check_shared_contract.py)
7. Run the six handoffs in the shared contract against the other two products before the first release. They cannot run until ColorGrade and MonitorKit exist, so they gate the release and not the merge. No migration note is needed while the three are in development.
