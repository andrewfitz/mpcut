# Still-image implementation audit

The review covers the still feature and the existing code it relies on, from opening an image to reopening the exported movie. The comparison build was the packaged still release based on `30b3b28`. The fixes were assembled against its saved source tree so that concurrent transcript changes would not enter the test package.

| Area reviewed | Findings and fixes |
| --- | --- |
| Import and decoding | GUI, CLI and MCP now inspect and fingerprint the same open regular file. Image I/O reads from that file descriptor. Rendering checks the expected file generation, including change time. Compatible AVIF sequence brands and inconclusive JPEG XL headers now receive explicit handling. JPEG gain-map inspection avoids copying unrelated candidate rasters. |
| Project files and history | Normal saves use the same lock as revision-checked saves. Untitled recovery writes use their existing draft lease, avoiding a second acquisition of the same lock. Paths containing a symlink followed by `..` resolve to the file the OS will open. Still-only projects validate their total frame count. The v2 schema agrees with the reader on ProRes containers, nullable crops and still IDs. |
| Ordinary and multicam editing | Option-drop respects replacement intent. A still drop shows its target time, and a multicam insert uses the cadence at that position. The ordinary timeline reserves space for the assets lane. Multicam file import and relink can be cancelled without blocking the editor. |
| Preview and JPEG review | Preview and review use the program canvas, including sample aspect ratio and rotation. Review and live preview verify the linked artwork. Camera fallback frames carry their source transfer across cuts, and an unavailable camera interval clears pending frame requests. |
| Generation and muxing | Cache keys account for effective dimensions and bitstream filters. MOV inspection recognizes compatible Main10 HEVC description changes when reopening stitched camera and generated footage. The native writer and probe now use the same registered-message parser for dynamic HDR, so unrelated user data can contain the same identifier bytes. The writer checks picture clocks during preflight and keeps track durations exact when staged MOV clocks differ. |
| Sound | Silent selections retain the chosen track format. Compatible big-endian PCM can retain its numeric samples through byte-order conversion. Unsupported automatic PCM conversions, explicit MP3 or FLAC requests, and AAC speaker-layout remapping are detected during planning. |
| Export choices and queues | Export rechecks sources after planning and checks cancellation before publication. Queue errors carry the placement and proposed boundary change. A verified MOV alternative can preserve ProRes camera picture. Applying an offered alternative preserves the accepted audio action, codec and quality. |
| CLI and interchange | Final Cut XML import recognizes linked stills written as `asset-clip`. A native project written beside an imported interchange file retains portable relative paths. Conversions that would omit every item return an empty-project diagnostic with placement information. |
| MCP | Tool schemas distinguish replacement and insertion fields. Review can select a replacement even when its covered camera needs attention. Still JPEG output respects the requested preset. Read-only still listing remains discoverable under a sheet, and insert cadence follows the native assembly resolver. |

Still-only projects can be created in the GUI or with `mpcut still create`. The live MCP tools edit an existing picture timeline, including a still-only project opened from disk.

## Test results

The full corrected Swift suite ran 714 tests across the core and desktop targets. There were 708 passes, six opt-in benchmark skips and zero failures. The nine draft tests include a scheduled save with undo history under an active recovery lease. The open-GOP tier regression uses a recorded HEVC sample whose CRA and leading RASL pictures were verified, so its outcome does not depend on a hardware encoder choosing an open GOP.

The signed production CLI passed all 116 integration tests. Fifty covered still timelines, image formats, still-only projects and authoring, including the 32-test timeline matrix. The other 66 covered export modes, conversion, mixed timelines and multicam. These exercised AVC/AAC, ProRes/PCM, HEVC PQ and HLG, variable frame timing, retained camera packet identities and still-only delivery. The GUI and MCP tests exercised both timeline types, live mutations, native undo and redo, save and reopen, export preflight and review JPEGs. The packaged app passed the full live MCP suite and three native editor/Video Monitor checks. Package verification checked its ad-hoc signature, all 90 MCP tools and both offline documentation resources. A CLI interruption test returned exit code 130 and left no output project.

## Verification boundaries

Automated checks can examine encoded or decoded pixels, packet hashes, clocks, tags, edit history and window state. Verification of emitted HDR highlights requires an HDR display running with EDR headroom. Independent placement and changes in headroom across two physical monitors also require a two-display setup. The available display reported headroom 1.0. The macOS 14 deployment floor, Final Cut Pro playback and native Resolve playback remain unverified. The converted-project tests verified the interchange files. A separate CLI help-discovery check on the shared working tree reported an unrelated mismatch in the concurrently edited transcript flags.
