# Multicam Mix and synced audio replacement

## Editor behavior

Add **Mix** as the fourth multicam audio mode beside Fixed, Follow, and None. On first entry, select the configured audio stream of each camera that has one. For a typical two-camera edit the timeline plays both, and export produces two separately selectable audio tracks. List other embedded streams and external recordings as choices. Show camera or recording name, stream, and channel layout. Keep the order visible and stable through save, reopen, and export. Require at least one selected lane in Mix. None already handles a silent timeline.

Give each lane a label and a colour slot from a fixed palette, assigned when the lane is created and kept through reorder, save, and reopen. Lanes stay separate in the project whatever the export delivers, so transcription and word editing can address each one.

A lane represents one user-selected soundtrack. A stereo pair or a 5.1 stream occupies one lane. For a camera with successive physical recordings, the camera's default lane follows that camera's recording coverage and configured stream. Selecting a specific recording and stream explicitly pins that lane to it. Tag a lane target as a camera or as a recording and stream, because an angle shares its ID with its first recording. Refuse a second lane that resolves to the same source, stream, and placement. Picture switches leave all selected lanes running. Preserve existing per-switch audio choices in the project so returning to the previous mode restores them. Preserve the Fixed selection and the Mix lane list the same way, so every mode switch is lossless. Assembly cuts, repeats, and reordering apply identically to every lane.

## Export

Expose an **Audio output** choice independent of the picture export mode. Carry audio delivery as a separate field through core export rules, the engine, dry runs, queue snapshots, and the app/CLI/MCP entry points. The engine currently gates conversion on picture Encode mode. Resolve the picture action and audio action independently, including copied picture with rendered sound. Show the delivery summary before export, for example “2 audio tracks · mono + 5.1 · stream copy.”

| Choice | Delivered audio |
| --- | --- |
| Separate tracks (default) | One track per selected lane, in displayed order. Preserve each original codec, sample rate, channel layout, and supported presentation edits. Compressed inputs stay in their original compression format with no generation loss. |
| Downmix to mono | One rendered, one-channel track containing every selected lane. |
| Downmix to stereo | One rendered, two-channel track containing every selected lane. |

Audio output combines with the existing audio action, applied per lane:

- **Copy** copies every lane or fails naming the lane. It is the default for separate tracks.
- **AAC** or **PCM** renders every lane, or the downmix, in that codec.
- **Auto** tries copy for each lane and renders only the lanes that cannot be copied, as it does per track in the still export path today. The delivery summary names each rendered lane before export.
- **Remove audio** writes no audio track and ignores the lane list.

A downmix is always rendered, so Copy is unavailable with it. A copied lane follows the existing per-codec copy rules for the container. Rendered sound follows the current container rules:

| Container | Rendered lane or downmix |
| --- | --- |
| MOV | PCM or AAC |
| MP4, M4V | AAC |
| MKV | PCM |
| WebM | Refused. No rendered codec is available for WebM today. |

Run the existing sound resolver independently for each copied lane. Check compatibility between spans joined into the same output track. Different output tracks may have different formats. Validate track count, codec/container support, source coverage, packet boundaries, priming, and presentation timing before writing. Identify a failing lane and output range and offer eligible alternatives. Never silently transcode, omit a lane, or shift a late source to zero. Single-track containers require a one-track delivery choice.

Validate the actual edges of each lane’s coalesced audio spans. A picture-only switch inside a continuous audio span creates no audio boundary. At an audio edit, validate both source presentation time (including media origin) and output time using the existing codec and container rules. For PCM and supported AAC edits both times must be on the relevant sample grid. For packet-copied formats apply the existing packet-boundary checks. Offer a moved cut only after replanning and checking the picture and every affected copied span.

For separate tracks, **Copy** preserves supported source presentation edits, including the existing declared leading PCM delay in MOV. When coverage leaves an interval that requires new silence samples, Copy refuses that lane and reports its output interval during dry run. This applies to interior gaps in PCM as well as compressed audio.

Under **Auto**, prefer the existing retained-PCM treatment for a compatible gapped PCM lane in MOV, or in WAV/WAVE or CAF for eligible sound-only exports. Reuse the still writer’s checks for sample format, rate, layout, and retained sample counts. Report “retained PCM samples + generated silence” with the lane ID and gap ranges. For other eligible lanes or containers, Auto can render with a supported codec, including PCM in MKV. Report the actual codec and generated intervals per lane before export. Explicit PCM or AAC delivery uses the regular render path. Each unaffected lane keeps its own selected treatment.

Generalize the one-sound staging path in `MulticamEngine` and `MulticamMux`. Pass the ordered staged sounds to the existing `MulticamMOV.combine(picture:sounds:output:progress:)` overload used by `StillExportWriter`. It already relocates tracks and chunk offsets and reconciles movie clocks. It passes each track header through unchanged, so set selection metadata explicitly: in MOV and MP4 put the lanes in one alternate group with only the first enabled, and in Matroska set the default flag on the first. Verify track order, edit lists, and selection metadata on the resulting file. Update `StillSound.multicamLanes` to consume every resolved lane and apply the existing inserted-still timing rules to each. For helper-backed containers, explicitly map every staged track in lane order. Players commonly select one alternate track for playback, so the export sheet should explain that the downmix delivers the timeline's combined sound as one track. Preserve existing source-identity checks and atomic publication.

For downmix, use the standard audio converter to bring each selected track to the requested mono or stereo layout and a common sample rate as needed. Define the layout conversion so it cannot add gain: a mono lane feeds both stereo channels at unity, a stereo lane becomes mono as the mean of its channels, and surround uses fixed coefficients normalized to sum to at most one. Average the converted tracks at each timeline sample, using equal weights of 1/N for N selected tracks. A gap contributes silence and the weights stay fixed across cuts and gaps. Per-lane gain is outside the first version, so several lanes with one live microphone play quieter than that microphone alone. This bounds each combined sample by the loudest converted input sample. Use the same average for preview and export, and encode the combined track once as PCM or AAC as supported by the container. Picture copy remains available when picture boundaries permit it.

## Replace a recording's audio

The current **Replace Source Audio** command in `MulticamReplacementAudio.swift` sets the whole program to Fixed and clears switch overrides. Label that existing scope **Replace Program Audio**. Add **Replace Track Audio…** on a recording/stream, accessible from Mix and camera audio controls.

1. Index the new file and choose its absolute audio stream. Keep it as a project source with identity and relink support. Bind the replacement to the selected original recording/stream. Follow, Fixed, switch overrides, and Mix then hear the replacement whenever they route that original stream. Other sources and picture switching retain their routes. A bound replacement takes its position only from its binding. Exclude it from group sync targets and from the sync sheet's offset writes.
2. Extend `MulticamSync.analyze` to accept the target camera recording and its original scratch stream as reference. Today it restricts the reference to a recording on the reference angle, takes its targets from the project's sources, and picks each stream from the source's configured one. Accept a draft source that is not yet in the project, and pass both absolute stream indices explicitly: the selected original camera stream and the selected replacement stream. Use that same pair for waveform matching, manual audition, and the applied binding. Changing either stream invalidates the previous sync result. Offer compatible timecode/Broadcast Wave alignment, waveform matching with drift evidence, and manual matching of a point in each recording.
3. Store a rational alignment relative to the target recording on the binding. Convert an analyzer suggestion to this relative value by subtracting the target recording’s group offset exactly once. At playback, replacement-local time equals group time minus the camera group offset minus the stored relative value. If a clap is at camera-local 12 s and replacement-local 2 s, replacement zero lands 10 s after camera zero. Moving the camera on the group timeline carries its replacement with it. A file reused by two cameras can have independent alignments. Account for each indexed stream's presentation start exactly once. Keep the confirmed alignment as rational time and step manual fine adjustment in replacement-stream samples. Export checks each actual span’s source and output boundaries independently. Preserve the confirmed sync position if preflight finds an unsafe copy boundary. Report coverage per binding: `inspect` places each source once by its own offset today, which cannot describe one file bound to two cameras.
4. Show overlap, uncovered edges, and start/end alignment before Apply. Fixed and Follow require continuous sound. When the replacement leaves part of the used recording uncovered, Apply requires a choice stored on the binding: keep the original stream there, or leave the interval uncovered. The lane resolver represents the resulting join or gap explicitly. Support audition and fine adjustment. Waveform matching searches within 30 seconds of its starting estimates. Allow a manually paired point to seed a search outside that range. When evidence is ambiguous, require manual alignment. Show the matched positions and residual discrepancy. A single anchor establishes alignment at that point and leaves drift unmeasured. Use distinct matches near both ends of the used overlap to verify alignment across that range within the waveform measurement resolution. Report measured drift if the discrepancy exceeds that resolution. When drift is detected, show the measured discrepancy before accepting a fixed offset. Time stretching requires rendered audio and is outside the initial copy-preserving implementation. Commit import, stream selection, and alignment together as one undoable edit. Cancel discards the draft. Reuse the alignment flow for an external program-wide replacement using the chosen reference recording.

## Transcripts, speakers, and word editing

Transcription already creates one track per project source and audio stream, with a role, an optional channel, and a speaker hint. Words carry their track, speaker, and source. Mix keeps that model. A lane is a view over those tracks. Store no lane-to-track or lane-to-speaker table.

1. **Mapping.** Join each lane's resolved source and stream spans to transcript tracks. A camera lane across a rollover maps to one track per recording. A stream split into channel tracks is one lane with several speakers. A replaced stream's lane maps to the replacement's track. A lane's speakers are those with recognized words on its tracks.
2. **Current Cut.** `TranscriptProjection.multicamWords` routes one stream per interval from `MulticamInterval.audio`, so in Mix every other lane's words would drop out or read as gaps. Build one route list per lane from the lane resolver. Add `lane_id` to each occurrence and coverage gap and keep `routed_source_id` and `routed_stream_index`. Include the lane in Mix occurrence IDs. Fixed and Follow output, including occurrence IDs, stays identical. Program silence in Mix means every lane is silent.
3. **Bleed.** A word heard on two on-air lanes is one occurrence. Choose its primary lane as Group view chooses its track, preferring recognized evidence, and list the others as `heard_on_lane_ids`. Words from separate attachments stay separate.
4. **Word edits.** Cuts ripple every lane. Removing a phrase reports overlapping speech on other lanes, naming lane and speaker. Tightening a pause is refused when any on-air lane has speech in it. It also requires transcript evidence on every on-air lane, because an untranscribed lane is not silence. `TranscriptEditTimeline.unavailableEvidence` reads the single soundtrack today. Key `distinctSpeech` by lane. An edit scoped to one lane, such as muting it under another speaker's word, needs rendered audio and is outside the first version.
5. **Replacement timing.** Track position comes from the source offset today, both in the job's session start and in projection. Take it from the resolved span. A transcript track is keyed by source and stream and has one session start, so a file bound to two cameras cannot be one track at two positions. Give each binding its own track, keyed by source, stream, and binding, and reuse the cached recognition so the file is recognized once. An alignment change flags the attachment for the existing Reconcile Transcript.
6. **Colour.** Show the lane's colour chip and label in the Mix lane list, the timeline lane row, the transcript passage header, filters, job setup, and coverage gaps. Always pair colour with the lane name. Keep it off word backgrounds, which selection uses. The chip shows for any track on a stored lane, in every audio mode. A track outside the lane list, such as replaced scratch audio, keeps today's neutral label. Colour follows the lane, not the speaker: speaker IDs are scoped to one attachment, and the speaker-to-angle preference lives in app storage that CLI and MCP cannot read.
7. **CLI and MCP.** Add lane ID, order, label, and colour slot to tracks list, speakers list, words read, search, and locate, coverage, and the edit plan's affected speech. Add a `lane_id` filter beside speaker, source, and track. Use the same lane IDs in multicam plan and inspect output. Stored and exported transcript documents stay at schema version 2. Their projection rejects unknown fields, so it carries no `lane_id`. It keeps the track ID with the routed source and stream. The track ID identifies the lane given the project, including for a file bound to two cameras, where source and stream alone do not.
