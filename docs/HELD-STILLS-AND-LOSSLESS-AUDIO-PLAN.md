# Held stills with lossless audio

Proposed implementation for MPCut. A five-minute recording with one cover image should export as one five-minute video sample and a full-length lossless soundtrack. A slideshow should store one independently decodable sample per visible image occurrence, including the last. Image changes must leave continuous sound continuous. “Lossless” here describes audio fidelity. Picture quality follows the chosen video codec and the project's existing color and framing settings.

## Required delivery targets

Ship every row below together. MOV with H.264 and ALAC is the proposed default for a new SDR project. The user can select any of the targets through the same export controls.

Each row expands across the listed picture codecs, color settings and audio codecs. For every row, both Smart Trim and Re-encode must produce one independently decodable sample per resolved hold. Lossless Copy retains its existing refusal for generated picture. In mixed edits, Smart Trim also checks compatibility with retained camera samples. See the [container rules](../Sources/MPCutCore/ExportRules.swift) and [still color rules](../Sources/MPCutCore/StillTimelineFormat.swift).

| File | Picture codec | Color | Lossless audio | Required playback |
| --- | --- | --- | --- | --- |
| MOV | H.264 | SDR | ALAC, PCM | AVPlayer and MPCut |
| MOV | JPEG | SDR | PCM | AVPlayer and MPCut |
| MOV | HEVC, ProRes | SDR, PQ, HLG | ALAC, PCM | AVPlayer and MPCut |
| MP4, M4V | H.264 | SDR | ALAC, FLAC | AVPlayer and MPCut with each extension |
| MP4, M4V | HEVC | SDR, PQ, HLG | ALAC, FLAC | AVPlayer and MPCut with each extension |
| MKV | H.264 | SDR | FLAC | MPCut fallback playback and an independent Matroska reader |
| MKV | HEVC, ProRes | SDR, PQ, HLG | FLAC | MPCut fallback playback and an independent Matroska reader |

The macOS 27.0.1 probe established the MOV, MP4 and MKV file combinations with independently generated fixtures. AVPlayer sought into the final second of the MOV and MP4 samples. FFmpeg read the MKV, while AVFoundation declined it. M4V is included because MPCut already exposes that extension. Verify every row with files produced by the bundled app. The other matrix entries are implementation and verification requirements. [QuickTime sample timing](https://developer.apple.com/documentation/quicktime-file-format/time-to-sample_atom/time-to-sample_table) · [Matroska final block duration](https://www.rfc-editor.org/rfc/rfc9559.html#section-5.1.3.5.3)

## Implementation order

1. **Prove the existing movie writer with one held picture.** The [shipping FFmpeg build](../scripts/build-ffmpeg.sh) disables encoders by default. Add ALAC and MJPEG to its explicit allowlist and retain the existing FLAC encoder. First run two smoke exports with the helper resolved inside the built app bundle, one MOV/H.264/ALAC and one MOV/JPEG/PCM. Assert the helper path and inspect the resulting codecs and video packets so a system FFmpeg cannot mask missing encoders.

   Parameterize the existing still export integration fixture over every target above, with one ten-second hold and two unequal holds. In Smart Trim, construct a schedule with one run, count one, and the exact resolved hold duration. Keep the encoder's staging cadence separate from that presentation duration. Exercise the existing helper probe, `MulticamMOV.retimeStill`, packet assembly, sound combine and final verification. Inspect the published file for exact PTS, duration, sync status and packet count. Add eligible targets to the still-specific container rules and still-project format validation. For MOV/JPEG, extend the existing still encoder settings and sample-description checks with JPEG video, using the existing framed and color-managed image as input. For MP4 and M4V, verify FLAC survives lane staging and final track assembly.

   For MKV, reuse timed MOV staging for the generated picture and the existing FFmpeg-backed mux path in the still writer. Inspect Matroska block timestamps and durations after the final mux. The existing [Matroska duration helper](../Sources/PacketWriter/matroska_duration.c) updates duration metadata. Verify the video block itself covers the final hold, and use an explicit block duration where the muxer would otherwise lose it. Use the current one-millisecond MKV packet clock. For generated stills, round internal image changes to the nearest tick (ties forward) and round the final held-picture end up to the next tick if needed. Compute every boundary from its absolute program position, then subtract adjacent boundaries for block durations. Exact boundaries stay exact. Preflight reports requested and written times, with at most half a tick of internal displacement and less than one tick of final overhang. Refuse a schedule that collapses an image to zero ticks or would shift a required camera-copy boundary. Preserve the exact audio samples and audible extent. Have final verification compare the published picture against these planned block boundaries and sound against its own sample clock. Retain exact picture timing for MOV-family targets. Reopen with [MPCut’s fallback reader](../Sources/MPCutApp/FFPreview.swift) and test seeking backward from EOF and directly into a long hold.

2. **Plan holds on the resolved picture timeline.** Offer “One frame per still” alongside the current timing in export settings. Default it on for the new image-and-soundtrack workflow. Preserve earlier settings and queue snapshots through a default on decode. Construct a hold after resolving the export selection, so a range starting halfway into an image gets a fresh first sample at output zero. Combine adjacent windows from the same visible placement when asset, framing, color and occurrence continuity agree, even if an underlying camera or sound edit splits them. Preserve distinct placement boundaries and source-occurrence reporting. For mixed projects, apply holds only to generated still spans and run the existing camera-boundary and HDR checks at each return to footage. Carry the same held schedule through full conversion and verify the final sync flags in both modes. An explicit held-timing request must fail preflight if the selected path would expand it to cadence frames. Use exact rational times and the schedule's clock limits. Report an unrepresentable hold in preflight with a usable timing alternative.

3. **Make a recording audible in a still-only project.** Add an optional soundtrack reference to the still sequence, using MPCut's existing clip path, selected track, source range and identity conventions. Image-first users can attach a recording. A recording plus a single image should offer “Fit image to soundtrack” and set the hold to the recording's exact audible sample extent. Today both project validation and the still format's target-stream builder require whole video frames. Allow an exact fractional final hold for this workflow while keeping the edit grid available for ordinary placements. Feed the soundtrack into `StillSoundPlanner` as a continuous source span on output time. Use the same mapping for playback, waveform, range export and scrubbing. An existing movie or multicam project with Replace Picture already has a sound source and needs only the new picture timing option.

   Start the soundtrack at program zero. Define a shorter export selection by intersecting its output range with the recording. If later picture edits extend beyond the recording, show the trailing silence in preflight. If they shorten the program, show the trimmed sound range. Keep the recording continuous across image moves and image changes. Preserve Insert Still's ripple-and-silence behavior for existing source-backed projects. Carry the optional reference through save/reopen, undo, relative paths, Project Media relink, queued source snapshots and interchange loss reporting. Update the project schema and reader compatibility checks alongside serialization. The current inherited sound-layout reference has different semantics and must retain them for existing selections.

4. **Preserve audio samples through export.** Prefer packet copy for a compatible lossless track when its requested range is copy-safe. For PCM input or an edit requiring sample-accurate conversion, extend the existing audio conversion planner and staged writer with ALAC and FLAC, mapping each action to its supported containers. Give explicit lossless requests a precision-preserving branch in the shared converter. Keep integer samples in an integer path of sufficient precision through edits and trims. Bypass automatic resampling, layout conversion, downmix and float32 staging of high-precision integers. When an edit or a requested mix changes sample values, report that treatment explicitly and offer it separately from source-sample preservation. Check source precision, channel layout, sample rate, sample count and destination mux support before offering a lossless action. For floating-point or greater-precision PCM that cannot round-trip through the selected lossless encoder, offer a verified precision-preserving PCM MOV option or report the limitation. Keep generated silence sample-aligned. Preserve independent tracks unless the user requests a mix. Distinguish copied audio, losslessly encoded PCM samples, generated silence and downmix in the report. A lossy source copied or decoded into ALAC or FLAC should retain its source codec in that report. Before publication, extend the [final track verifier](../Sources/MPCutCore/StillExportWriter.swift) to check codec, precision where signaled, sample rate, layout, channel order and audible start/end against each planned track, including the single-track case. Check coded padding against the intended audible sample count. Keep decoded per-channel comparisons in release fixtures. An explicit lossless request must never fall back to AAC.

5. **Expose one plan across the app, CLI, MCP and queue.** Treat the saved codec and container as export defaults. The [current resolver](../Sources/MPCutCore/StillExport.swift) chooses the saved codec over the request and rejects a different container. Represent omission explicitly. Resolve explicit codec, container and destination extension first, reject conflicting explicit choices, then fill omitted values from the saved format. Build and validate the effective output description from that result, preserving the project canvas and color policy. Carry it into the writer and queue snapshot. Choosing a delivery format leaves the saved project available for subsequent exports with its authored defaults.

   Thread the timing choice and audio action through the existing export request and dry-run, rule discovery, export sheet, saved queue snapshots and project-render commands. Use the existing still authoring entry points for the soundtrack attachment and fit operation. Report the generated video sample count, exact picture duration, output codec and per-track sound treatment before writing. Keep offline-image behavior for audio-only exports and strict copy refusal for generated picture. Document the working combinations and examples in the existing still and export guides after verification.
