# Transcript-driven editing in MPCut

## Outcome and scope

An editor opens a multicam interview, chooses **Transcribe with Transcriberrr**, and gets one searchable conversation mapped to the audio streams that recorded it. Searching a guest’s answer shows the original words, the tracks that heard them, the camera angles covering that moment, and each occurrence retained in the cut. The editor can mark the answer, replace a take, tighten a pause, switch camera, or queue an excerpt using MPCut’s existing cut and export rules.

This plan covers the complete workflow in the GUI, standalone CLI, and live MCP interface. It includes ordinary video and audio-only sequences, multicam groups and assemblies, saved and unsaved projects, and import of transcripts made elsewhere. Transcriberrr owns transcription, alignment, diarization, and cross-track reconciliation. MPCut owns audio extraction, media identity, clocks, project attachment, search, editorial decisions, and export preflight. The deliverable is editing metadata and ordinary MPCut edits. Caption styling, burned-in subtitles, and audio processing for the finished movie are outside this plan.

Everything here is in scope. [Delivery order](#5-implementation-and-verification) is phased so each phase ships a usable result and the riskiest work, mixed-track reconciliation, does not block the rest.

## 1. Transcriberrr session contract

Use the installed local Transcriberrr batch helper, found by bundle identifier as MPCut already finds Resolve and Final Cut. Run `capabilities` before submission and require the session schema version. Expose a helper override for development and CLI installations, following `MPCUT_FFMPEG_HELPER`. Give an actionable error if the helper, session support, selected engine, language model, or requested diarization is unavailable. Engine limits come from `capabilities`: for example the Apple engine needs macOS 26 and does not diarize, and the diarizer model bounds the speakers it can separate on one mixed track. Importing an existing transcript requires no helper or model. Realtime streaming is unnecessary for recorded footage.

| Record | Required behavior |
|---|---|
| Session | Carry a contract version, job ID, language/engine options, and an explicit inventory of tracks. A multicam group is one session. In an ordinary sequence each referenced media file is its own session, since unrelated files share no conversation. Submit each unique input stream once even when it appears repeatedly in an edit. Inventory every audio-bearing camera stream and external recorder stream, including off-air sources, and silent cameras as coverage-only. |
| Track | Carry a stable `track_id`, project source ID, stream evidence identity, the binding in section 2, channel selection if applicable, descriptive name, `role` (`isolated_mic`, `mixed_audio`, or unknown), optional `speaker` hint, and a `recognize` flag. Camera names and speaker names are independent. Distinguish the two streams in one movie and two cameras with identically named files. |
| Audio and timing | **MPCut extracts the audio.** For each track MPCut decodes the selected stream and channel with its own decoder and writes 16 kHz mono PCM, Transcriberrr’s working rate. Sample 0 corresponds to a source time MPCut records exactly. The manifest gives `start_frame`, the first sample’s position on the session timeline in 16 kHz frames, for cross-track comparison. It is signed, because a source can begin before group zero. Transcriberrr never selects a stream or reads container timing in session mode. Avoid rendering the assembled program as the sole input. |
| Native result | Per track: verbatim word fragments with integer start and end sample indices local to that track’s audio, deterministic utterance and word IDs stable within a result version, and local speaker indices for diarized tracks. Per session: session-wide speaker IDs, optional display names, and for each conversation word a representative rendition plus its supporting observations. Mark each observation `recognized` (words transcribed on that track) or `audible` (level evidence that the track heard the moment). Retain overlap and ambiguity. There is no confidence value today; the field is optional and absent means unknown. |
| Completion | Emit machine-readable progress, per-track results or failures, and a terminal result identifying the request. Publish each track result atomically as it completes. Report partial coverage and allow retry of failed tracks without duplicating accepted words. Cancellation, lost completion responses, and app relaunch follow the job record in section 4. |

**Recognition scope.** By default set `recognize` on every isolated mic and on the mixed tracks needed to cover speakers without one: the routed program source first, then the reference angle. Every other inventoried track contributes `audible` evidence from 20 ms level frames, which Transcriberrr already computes for bleed comparison, at no recognition cost. In an ordinary sequence recognize each file’s first audio stream, or the replacement track a clip plays, and inventory the rest. Full recognition of every track is an explicit option. Show an estimated run time before starting, from the measured real-time factor of the chosen engine.

**Transcriberrr changes.** Extend the two apps together. The session manifest and result are new versioned documents; an older helper rejects the manifest outright, so check `capabilities` first. Keep the current transcript JSON reader and writer compatible. In session mode use the manifest’s roles, speakers, and `start_frame` in place of file-name speaker discovery and the assumption that tracks start together. Add a **reconcile-only** command that rebuilds the session result from stored per-track results, level frames, and new starts without running recognition. MPCut removes its extracted audio after completion or cancellation.

**Speaker and duplicate handling.** Recognize isolated speaker mics with their supplied identities. **A track result depends only on its own stream.** Today’s session path mutes bleed before recognition, which makes each result depend on the other tracks and their starts. In session mode recognize each track unmuted and apply the same level comparison at reconcile time: words a track heard as another speaker’s bleed become supporting observations of that speaker’s words, so each line still appears once. This keeps results cacheable and lets an offset change re-reconcile without recognition. Compare it with mute-first on the labeled fixtures; if it is materially worse, keep mute-first and add the mask identity to the result key, accepting that an offset change then re-recognizes isolated tracks. Diarize recognized mixed tracks and reconcile their local speaker indices to session IDs using isolated-mic evidence and aligned turns. When several tracks are recognized, align candidate word runs using session time, wording, and surrounding words, and choose a representative rendition while retaining each contributing track’s observation. Identical words from two people, an immediate repeated “yes,” and conflicting alternatives must remain distinguishable. Surface uncertain matches for correction. A camera can hear several people, and one speaker can be heard by several cameras. A preferred camera for a speaker is an optional editorial choice.

**Matching has one owner.** Transcriberrr computes every cross-track match. MPCut stores the result and the editor’s overrides, and never matches words itself. Imported transcripts carry whatever matches they already contain.

## 2. Storage, clocks, and project lifecycle

**Storage**

| Data | Home | Lifetime |
|---|---|---|
| Per-track recognition results | A new versioned `.cutdb` section beside the media, keyed by stream, channel, engine, model, and language, and stamped with the stream evidence MPCut already records. | A recognition cache. Immutable per result. Shared by every project using that media, including untitled projects and CLI runs on a bare file. Invalidated by the existing evidence comparison. Regenerable. |
| Session results and imported transcripts | A project transcript store beside the saved `.cut`, referenced by relative path and SHA-256 like still assets. Content-addressed, so versions referenced by undo stay available; prune unreferenced versions on save. | What the project shows. A session result is self-contained: the conversation’s words, speakers, and observations in stream time. Reading, search, projection, and editing need only this store. Imported SRT, WebVTT, and JSON cannot be regenerated, so MPCut copies them in. |
| Bindings, speaker names, identity and text corrections, match overrides, named selects | Fields of the `.cut` document. | Authored. Undoable. Anchored so it survives a new result, as below. |

- Keep source-local observations immutable per analysis result. Keep original timings and wording available for inspection. A text correction changes transcript metadata. Removing the corresponding media requires an explicit timeline edit.
- **Format.** Add `schemaVersion` 3 with a `transcripts` root field. As with version 2, write version 3 only when the project holds transcript data, and keep writing versions 1 and 2 otherwise. Versions 1 and 2 remain readable. Publish a version 3 JSON Schema beside the two existing closed schemas, and update the reader’s unknown-field checks, validation, path rebasing, sidecar exclusions, destination-collision checks, and the media retained by history.
- **Undo.** A history step is a whole-project snapshot stored as per-field deltas, limited to 500 steps and one million records. Store corrections as sparse overrides and add their delta type. Word IDs are stable only within one result version, so anchor each override and named select by stream binding, stream-time span, and original wording, with the word ID as a hint. A new result re-anchors by span and wording and flags what no longer matches. Never store transcript text for uncorrected words in the `.cut`. Attaching, detaching, and choosing a result version are undoable edits that change only references.
- **Untitled projects.** The draft folder holds exactly one document and is removed on discard. Keep an untitled project’s transcript store in a separate area keyed by the draft, move it beside the project on first save, and delete it with the draft. Save As copies the store; this is new behavior, since Save As currently copies no assets. A project moved without its media sidecars still reads, searches, and edits from its store. It needs the sidecars or the helper only to re-reconcile after an offset change or to recognize again.
- When a sidecar cannot be written, report it and offer the result as native JSON the project imports. On reopen, distinguish missing transcript, offline source, and changed media using the existing refresh states. Offer explicit relink/rebind where identity cannot be verified. The underlying edit remains usable if the transcript is missing.
- **Interchange.** Conversion to other editors carries the timeline only. Report attached transcript data as a named loss.

**Clocks**

- Use half-open intervals throughout. Observations are stored in **stream time**: the exact source time of extracted sample 0 plus sample index over 16,000. Declare the source clock explicitly, because the same movie has two: ordinary sequences measure from the primary track’s start, and multicam keeps the movie’s presentation clock. Store observations on the presentation clock and convert at the sequence boundary.
- For multicam, **group time = source time + source offset**. Intersect the result with each retained assembly occurrence and translate that intersection to output time. For an ordinary clip, intersect with its retained source range, then add its sequence start and subtract its source in-point.
- **Stream binding.** A multicam binding is source ID plus absolute stream index. An ordinary sequence stores no stream choice unless audio was replaced, where it stores a track ordinal with `file` and `originalFile`. Bind sequence transcripts to the original file and absolute stream index, map the ordinal through the media index, and treat a replacement as a separate stream.
- **Source** includes all original speech, including deleted takes. **Group** is the synchronized conversation. **Current Cut** follows actual output order and program audio routing, including fixed master, follow-camera, switch overrides, replacement audio, silence, trims, repeats, and reorders. Build it from the routing spans the multicam plan already produces. Inserted still cards advance output time and carry no dialogue; replacement stills change picture only; assembly indices count cards. Distinguish a transcript observed on the routed track from one inferred using another microphone. Mark coverage gaps and partial words explicitly.
- Recalculate projections after changing source offsets, routing, switches, stills, or the assembly. Projection never needs the helper. An offset change marks the session result stale: per-track words keep projecting, cross-track matches show as stale, and reconcile-only refreshes them. Replacing audio invalidates the affected stream binding. Camera changes alone do not require speech recognition. Use stable occurrence references scoped to the edit revision.

## 3. Editing experience

| Editor request | Behavior |
|---|---|
| Find the line | Search exact phrases and normalized wording with punctuation/case tolerance. Filter by speaker, source, track, or occurrence. Show neighboring words, track evidence, time, and all matches. Preserve verbatim wording for display. Allow next/previous match and context playback. |
| Read and navigate | Open a keyboard-accessible transcript beside the viewer. Multicam adds a Transcript tab to its inspector. The ordinary sequence editor has no side panel today and gains one, with the presentation tools updated to match. Switch between source/group and current cut. Click a word to seek, drag or extend by keyboard to select a phrase, and follow the active word from timeline playback or scrubbing. Distinguish simultaneous speakers, partial words, and untranscribed material. |
| Trim, split, or remove words | Convert a word edge, phrase, or intervening gap into native marks or selection. Support split, trim start/end, delete range, and restore through undo. Default phrase bounds span first word start through last word end, including internal pauses. Leading/trailing padding and frame nudges are explicit. Deleting time on a mixed track also affects overlapping speech; show that in the preview. |
| Tighten pacing | Select a gap between phrases, inspect duration and waveform, specify retained duration, and protect intentional pauses. Integrate with existing silence review and routed pauses. Sequence pause protection is held in memory today; persist protections made from the transcript in the project. Display the requested and achievable duration. Handle overlapping words as concurrent speech rather than a negative pause. |
| Compare and join takes | Show matching readings with adjacent dialogue, source and occurrence, and playable context. Keep named word-range selects, stored in the project and kept after every use leaves the cut. Assemble, insert, reorder, or replace with ordered ranges from multiple inputs through the new multi-source ordered edit. A proposed transaction reports duration, cut-boundary, and export-tier changes and commits as one undoable edit. |
| Follow a script | Import or paste script text. Return candidates per beat with exact, approximate, partial, missing, and ambiguous matches. Flag a qualifier present in one take and missing in another. Review alternate takes, mark chosen passages, and use the same ordered range operation to assemble them. Expose the comparison as data so agents can apply their own editorial judgment. |
| Review restarts and fillers | Offer reviewable candidates for restarts, repeated phrases, and editor-specified filler terms. Show both surrounding passages and affected audio before accepting a cut. Support individual accept/dismiss and reviewing a batch of accepted ranges as one edit. |
| Cut multicam by dialogue | Select a speaker or word, list available angles and source-frame locations, and switch at a resolved cut point. Expose whether the operation changes a shared group interval and which replays are affected. Scope occurrence-only trims to the assembly. Keep speaker-to-angle suggestions editor-configurable. |
| Pull clips and notes | Expand a quote by word, sentence, or speaker turn, include the preceding question, and queue its captured media ranges with a name. Queue entries have no editor-set name today (sequence rows show the first file name and multicam rows the project name), so this adds one to the queue model, its row, and the queue tools. Copy a quote with source/stream, speaker, time, and occurrence references. Export source, group, or current-cut dialogue as native JSON, readable text, SRT, or WebVTT with the selected clock identified. |
| Correct attribution | Rename speakers, merge or split mistaken identities, assign selected words to a speaker, and resolve duplicate/conflicting observations. Show track evidence during review. Retain corrections across project reopen, and flag conflicts when refreshing a result. |

**Boundary review is shared with the existing editor.** A word time is an estimated speech boundary. Resolve it against indexed picture frames or audio sample clocks, then use the chosen export mode’s actual eligibility checks. Show requested, resolved, and available copy-safe alternatives, adjacent words affected, duration impact, any edge encoding, and the resulting export tier from the existing tier report. Handle variable frame rate, delayed streams, and no valid copy-safe alternative. Apply only the reviewed boundary policy. Preserve source recordings and program audio routing.

## 4. GUI, CLI, and MCP parity

The command and tool names below are proposed interfaces. Keep the same IDs, data fields, coordinate spaces, edit outcomes, and error meanings across all three. CLI targets a media file or saved project. MCP targets a live project, including an unsaved window, or uses file jobs for the same saved-file operations. File jobs run the bundled CLI through the app, so they also need the app running with local control enabled. The GUI operates on that same live document.

| Capability | GUI | CLI under `mpcut transcript` | MCP operation family |
|---|---|---|---|
| Discover inputs and compatibility | Transcript setup, audio-stream list, engine capabilities | `capabilities`, `tracks` | Read capabilities and track inventory |
| Transcribe all tracks or a subset | Transcribe, per-track progress, cancel, retry, auto-attach | `transcribe`, `status`, `cancel`, `retry` | Start/poll/cancel/retry transcript job |
| Import, inspect, bind, or detach | Import Transcriberrr JSON, SRT, VTT; inspect binding; relink or detach | `import`, `inspect`, `bind`, `detach` | Manage attachments and review unmatched inputs |
| Read, search, and navigate | Source/Group/Current Cut, phrase search, speaker filters, seek | `read`, `search`, `locate` | Paged read/search/locate; seek or select in live editor |
| Review takes or script | Compare passages, align script, review suggestions | `compare`, `align-script`, `suggest` | Compare candidates, align beats, list suggested ranges |
| Correct metadata | Edit speaker/text, resolve uncertain matches | `correct` with a typed change | Correct metadata with revision and undo |
| Select, review and edit | Marks, named selects, preview, apply, undo | `select`, `plan`, `apply` | Resolve word selections, plan, commit, and native undo |
| Deliver excerpts or transcript | Named queue entry and transcript export | `queue` to a saved range list for bulk export; `export` | Add captured live queue entry; export transcript or file job |

- **Job record.** Transcription can outlast every existing receipt: analysis receipts are in memory and revoked when the window closes or local control turns off, file-job and replay records expire after ten minutes, and quitting cancels all jobs. Keep one durable record per transcript job on disk with its job ID, input evidence, options, per-track state, and Transcriberrr progress file. The helper runs as a child and stops when MPCut quits or is cancelled. Resume uses Transcriberrr’s `--progress-file --resume` and skips tracks whose results are already in the sidecar. On relaunch MPCut lists resumable jobs and re-attaches finished tracks by evidence. A local-control toggle or a regenerated project handle revokes agent access, not the job.
- **CLI.** Follow existing conventions: `--json`, `--stdin`, `--input FILE`, `mpcut help transcript --json`, rational times, and explicit source/group/sequence/assembly spaces. `transcribe` runs synchronously with `--progress none|stderr|jsonl`, `--policy reuse|resume|restart`, and `--operation-id`, as `scenes` does. `status`, `cancel`, and `retry` in another process read the same job record. CLI locate returns coordinates; GUI and live MCP can also move the playhead.
- CLI edit planning is read-only. `apply` and `correct` take `--out-project FILE` or `--in-place`, as `still` does. In-place verifies the SHA-256 of the project bytes it read and publishes atomically. A CLI queue operation writes the ordered source list directly rather than depending on an open GUI. Reuse existing export commands for media delivery.
- **MCP.** Add a small set of action-style tools, as `sequence_control` does, rather than one tool per verb, plus `file_transcript` for saved files. Each needs a descriptor in `MCPResources`, a dispatch branch, a return contract in the reference generator, coverage rows, and Go integration tests. A request must answer within five minutes and four mebibytes, so every long operation returns a job at once and every transcript read, search, and evidence listing is paged.
- Live MCP requests carry the project handle, expected revision, result version, stable word and occurrence IDs, and operation ID where applicable. Reply with resolved ranges, affected occurrences, history action, resulting revision, or job ID. Enforce current local-control settings, cancellation, and existing retry semantics.
- If the human makes a timeline edit while recognition is running, attach results to still-matching source identities and project them onto the latest edit. Revalidate before timeline mutation. On ambiguity return candidate IDs. Never silently select the first replay. Keep a partial job distinguishable from a fully transcribed session.
- Existing Transcriberrr JSON can be imported directly. Honor word versus segment precision, optional labels, and the per-track source, speaker, and offset list in merged files. SRT and WebVTT imports preserve cue timing and any explicit speaker information. Cue-only imports support cue selection and mark word-precision operations unavailable. Allow re-export or conversion without running recognition.

## 5. Implementation and verification

Deliver in this order. Each phase ends with its own check on all three surfaces it touches, and the product is usable after every phase.

|---|---|---|

Transcript pane, CLI `import`/`inspect`/`read`/`search`/`locate`/`export`, paged MCP read. | Scenario 4 passes. **Fixtures and measures**

- Neither repository has a recorded speech fixture. Record a short, licence-clear interview set: two cameras, one isolated lav, a late-starting camera with delayed audio, an interruption, and three readings of a scripted line. Label words, speakers, and overlaps by hand.
- **Sample-zero fixture.** A file with a click at a known source time and AAC priming, plus one with a delayed audio stream. The click’s position in MPCut’s extracted audio and on MPCut’s source clock must agree within one 16 kHz sample. Both repositories decode the contract examples identically.
- Deterministic tests use a stub helper that replays fixture results and run everywhere. Tests against the real helper need the installed app and multi-gigabyte models, so they run only where those are present and are reported separately.
- Before phase 3, run the real helper on the labeled set and record the baseline here: word timing error, attribution mistakes, duplicate utterances, missed overlaps, and real-time factor per engine. Phase 4 repeats the run to compare mute-first with reconcile-time bleed handling. Later phases must not regress it, and phase 7 sets its thresholds from it.
- Measure opening, searching, and paging a multi-hour, multi-track project, and the history cost of corrections.
- Publish CLI help, generated tool schemas and reference, the offline guide, and runnable examples for one ordinary and one multicam project. The GUI walkthrough is manual except where the Accessibility-driven script covers it.

**Required acceptance scenarios**

1. Two cameras and an isolated host lav record an interview. Camera B starts late and contains delayed audio. One guest interruption overlaps the host. Send every stream in one job, find a host phrase once with multiple evidence tracks, preserve the interruption, and seek to the correct frame or report a gap on each angle.
2. Use a fixed lav, then a switch-specific mic override and a silent interval. Repeat a passage, trim through a word, insert a still card, and reorder the assembly. Verify Source, Group, and Current Cut independently. Change a sync offset and verify re-projection without rerunning recognition, with matches marked stale until reconcile-only runs.
3. Search three readings of a scripted line, identify a missing qualifier, select parts of two takes, preview an unsafe word boundary and its tier change, and apply the chosen plan in one undo step. Export and inspect the actual copy/encode result. Reopen and confirm the timeline, transcript, selects, and speaker corrections agree.
4. Import legacy native JSON, merged JSON without word-level track provenance, segment-only JSON, SRT, and WebVTT. Preserve provided precision; surface ambiguous bindings. Export current-cut cues with repeated passages at their respective output times.
5. Start a job on an untitled project, edit while it runs, Save As, quit and relaunch mid-job, cancel/retry a failed stream, and replay a completion. Verify one attachment, no duplicate passages, preserved human edits, safe recovery after interruption, and clear status for replaced or missing media.
6. Issue the same word-addressed edit from each interface against identical input projects. Check exact retained ranges and undo state. Exercise ambiguity, stale revisions, absent helper, an older helper without session support, empty/silent input, partial failure, revoked live access, and a long paginated transcript. Run an agent-only walkthrough from discovery to verified export.

Completion requires both repositories’ contract tests, MPCutCore and editor tests, CLI fixture runs, live MCP integration, and a GUI walkthrough on the same fixtures. Heuristic speech recognition and speaker attribution are evaluated separately from deterministic media/time mapping, against the recorded baseline. Require exact agreement for the coordinate transforms and occurrence mapping.
