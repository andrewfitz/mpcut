# Transcript-driven editing in MPCut

## Outcome and scope

An editor opens a multicam interview, chooses **Transcribe with Transcriberrr**, and gets one searchable conversation mapped to the audio streams that recorded it. Searching a guest’s answer shows the original words, the tracks that heard them, the camera angles covering that moment, and each occurrence retained in the cut. The editor can mark the answer, replace a take, tighten a pause, switch camera, or queue an excerpt using MPCut’s existing cut and export rules.

This plan covers the complete workflow in the GUI, standalone CLI, and live MCP interface. It includes ordinary video and audio-only sequences, multicam groups and assemblies, saved and unsaved projects, and import of transcripts made elsewhere. Transcriberrr owns transcription, alignment, diarization, and cross-track reconciliation. MPCut owns audio extraction, media identity, clocks, project attachment, search, editorial decisions, and export preflight. The deliverable is editing metadata and ordinary MPCut edits. Caption styling, burned-in subtitles, and audio processing for the finished movie are outside this plan.

MPCut and Transcriberrr ship this workflow together. The [work packages](#5-implementation-and-verification) describe internal dependencies. Delivery requires the complete GUI, CLI, and MCP acceptance suite.

## 1. Transcriberrr session contract

For the explicit desktop or live MCP transcription action, use the installed local Transcriberrr batch helper, found by bundle identifier as MPCut already finds Resolve and Final Cut. Run `capabilities` before submission and require the session schema version. Expose a helper override for development and CLI installations, following `MPCUT_FFMPEG_HELPER`. Give an actionable error if the helper, session support, selected engine, language model, or requested diarization is unavailable. `capabilities` already reports each engine’s availability, minimum macOS, and whether it diarizes; the Apple engine needs macOS 26 and does not. It reports no speaker limit, and Transcriberrr’s own text describes the diarizer as both four-speaker and up to eight, so add a verified numeric limit to the session capabilities. Run the helper offline. When a model is missing, name it and download only on the editor’s explicit request; a model download is a separate Transcriberrr operation for command-line users. Importing an existing transcript requires no helper or model. Realtime streaming is unnecessary for recorded footage.

| Record | Required behavior |
|---|---|
| Session | Carry a contract version, job ID, language/engine options, an optional expected speaker count, and an explicit inventory of tracks. A multicam group is one session. In an ordinary sequence each referenced media file is its own session, since unrelated files share no conversation. Submit each unique input stream once even when it appears repeatedly in an edit. Inventory every audio-bearing camera stream and external recorder stream, including off-air sources, and silent cameras as coverage-only. |
| Track | Carry a stable `track_id`, project source ID, stream evidence identity, the binding in section 2, channel selection if applicable, descriptive name, `role` (`isolated_mic`, `mixed_audio`, or unknown, which is handled as mixed), optional `speaker` hint, and a `recognize` flag. Camera names and speaker names are independent. Distinguish the two streams in one movie and two cameras with identically named files. |
| Audio and timing | **MPCut extracts the audio.** For each track MPCut decodes the selected stream and channel with its own decoder and writes 16 kHz mono 16-bit PCM WAV, Transcriberrr’s working rate. Extraction uses the fully indexed source clock and is continuous on it: a delayed onset or a gap becomes silence, so a sample index maps linearly to source time. Sample 0 corresponds to a source time MPCut records exactly. The manifest gives `start_frame`, the first sample’s position on the session timeline in 16 kHz frames, for cross-track comparison. It is signed, because a source can begin before group zero, and is the exact start rounded to the nearest frame; MPCut keeps the exact value. Transcriberrr never selects a stream or reads container timing in session mode. Avoid rendering the assembled program as the sole input. |
| Native result | Return verbatim track-local words with integer sample bounds, deterministic word and utterance IDs within a result version, and diarized speaker IDs. A conversation word links to its observations. Mark words decoded on a track as `recognized` and uncertain cross-track associations as `inferred`, with their basis. Store 20 ms level frames separately as `activity` for audio-bearing inputs. Activity can coincide with a cough, music, or another person talking and cannot establish a word or speaker on that track. Track-filtered word search defaults to recognized observations and identifies inferred matches separately. Preserve overlaps and unknown confidence. |
| Completion | Emit machine-readable progress, per-track results or failures, and a terminal result identifying the request. Publish each track result atomically as it completes. Report partial coverage and allow retry of failed tracks without duplicating accepted words. Cancellation, lost completion responses, and app relaunch follow the job record in section 4. |

**Recognition scope.** Recognize every audio-bearing stream by default, including off-air angles, external recorders, and additional streams in ordinary media. Offer a faster explicitly selected subset. Record skipped and failed streams separately and display gaps in word coverage in GUI, CLI, and MCP results. Show the estimated runtime for the chosen inputs and engine.

**Transcriberrr changes.** Define one development contract for the native documents and session helper. Use explicit roles, speaker hints, signed starts, and clock declarations. Publish reusable per-track results and level frames before merging. Transcriberrr can reconcile stored outputs without models when the recognition inputs are still valid. Staged audio survives interruption and is cleaned up on completion, cancellation, or discard.

**Speaker and duplicate handling.** Diarize mixed tracks and map local identities to session speakers using aligned turns, recognized words, and isolated-mic evidence. Preserve competing observations, interjections, immediate repetitions, and genuine overlap. Benchmark unmuted recognition against muting bleed before recognition. With unmuted recognition an offset change reuses the track results and reruns reconciliation. With mute-first, include the effective mask digest in each recognition key. Recompute masks, rerun precisely the tracks whose recognition inputs changed, and reconcile the results. Preserve editor corrections or flag ambiguous anchors under either policy. Keep speaker identity independent of camera preference.

**Matching has one owner.** Transcriberrr computes every cross-track match. MPCut stores the result and the editor’s overrides, and never matches words itself. Imported transcripts carry whatever matches they already contain. Text comparison inside an attached transcript (search, script alignment, take comparison, and restart and filler candidates) is MPCut’s and needs no helper.

## 2. Storage, clocks, and project lifecycle

**Storage**

| Data | Home | Lifetime |
|---|---|---|
| Per-track recognition results | A new versioned `.cutdb` section beside the media, keyed by stream, channel, extraction and contract version, engine, model and its revision, language, diarization settings, and effective mask digest when muting is applied, and stamped with the stream evidence MPCut already records. | A recognition cache. Immutable per result. Reusable across projects and bare-file runs when the full recognition key matches. Regenerable. The sidecar drops sections it does not recognize whenever the file’s stamp changes, so add these keys to its preserved set while the stream’s audio evidence is unchanged. Add a cross-process claim, as scene scans have, so the GUI and CLI never recognize one stream twice. |
| Per-stream level frames | A `.cutdb` section keyed by stream, channel, and extraction version. | Engine-independent. Reconcile-only reads it. Preserved on the same terms and regenerable by extraction alone. |
| Session results and imported transcripts | A project transcript store beside the saved `.cut`, referenced by relative path and SHA-256 like still assets. One store folder per project, never shared between projects. Content-addressed. Write new entries before publishing the `.cut`, and afterwards prune entries the saved project no longer references. | What the project shows. A session result is self-contained: the conversation’s words, speakers, and observations in stream time. Reading, search, projection, and editing need only this store. Imported SRT, WebVTT, and JSON cannot be regenerated, so MPCut copies them in. |
| Speaker names, identity and text corrections, match overrides, named selects, pause protections made from the transcript | Fields of the `.cut` document. | Authored. Undoable. Anchored so it survives a new result, as below. |
| Bindings and the current result version | Fields of the `.cut` document, outside history. | Attachment state, as below. |

- Keep source-local observations immutable per analysis result. Keep original timings and wording available for inspection. A text correction changes transcript metadata. Removing the corresponding media requires an explicit timeline edit.
- **Format.** Extend the development `.cut` schema in place with a `transcripts` root field. Update the reader, writer, published schema, fixtures, validation, path rebasing, sidecar exclusions, and destination-collision checks together. Use the same schema for projects with and without transcript attachments.
- **Undo.** A history step is a whole-project snapshot stored as per-field deltas, limited to 500 steps and one million records. Store corrections as sparse overrides, one per corrected span and not per word, and add their delta type; every retained state counts them toward the record limit. Word IDs are stable only within one result version, so anchor each override and named select by stream binding, stream-time span, and a hash of the normalized original wording, with the word ID as a hint. A new result re-anchors by span and hash and flags what no longer matches. Never store transcript text for uncorrected words in the `.cut`. Attachment state is saved but is not history: attaching a finished job adds no undo step, leaves redo intact, does not change the timeline revision, and is carried across undo and redo. Maintain a transcript-state revision for edits to attachments, bindings, import origins, speaker or text corrections, and match overrides, including undo/redo. A prepared edit captures the timeline revision, transcript-state revision, and result identity. Validate all three as part of the commit. A mismatch returns a stale-plan result before any mutation. Detach is an explicit command.
- **Untitled projects.** The draft folder holds exactly one document and is removed on discard. Keep an untitled project’s transcript store in a separate area keyed by the draft, move it beside the project on first save, and delete it with the draft. Save As copies the store; this is new behavior, since Save As currently copies no assets. A project moved without its media sidecars still reads, searches, and edits from its store. It needs the sidecars and the helper to re-reconcile after an offset change, and the media and the helper to recognize again.
- When a sidecar cannot be written, the job still attaches its session result to the project store; report that reuse by other projects and reconcile-only are unavailable. A CLI run on bare media then writes its result to the requested output. On reopen, distinguish missing transcript, offline source, and changed media using the existing refresh states. Offer explicit relink/rebind where identity cannot be verified. The underlying edit remains usable if the transcript is missing.
- **Interchange.** Conversion to other editors carries the timeline only. Report attached transcript data as a named loss.

**Clocks**

- Use half-open intervals throughout. Observations are stored in **stream time**: the exact source time of extracted sample 0 plus sample index over 16,000. Declare the source clock explicitly, because the same movie has two: ordinary sequences measure from the primary track’s start, and multicam keeps the movie’s presentation clock. Store observations on the presentation clock and convert at the sequence boundary.
- For multicam, **group time = source time + source offset**. Intersect the result with each retained assembly occurrence and translate that intersection to output time. For an ordinary clip, intersect with its retained source range, then add its sequence start and subtract its source in-point.
- **Stream binding.** A multicam binding is source ID plus absolute stream index. An ordinary sequence stores no stream choice unless audio was replaced, where it stores a track ordinal with `file` and `originalFile`. Bind sequence transcripts to the original file and absolute stream index, map the ordinal through the media index, and treat a replacement as a separate stream.
- **Imported clocks.** The native JSON contract declares its clock. Single-source sample times resolve through the recorded sample-zero origin. Merged conversation times are session-relative. Prefer explicit source-local observations. When mapping a session time back to a uniquely identified source part, subtract its session start exactly once and apply its declared local origin. With a zero local origin, 65 s in a session on a part starting at 60 s seeks to 5 s in that part. If the part is ambiguous, expose the candidates and keep the session location. For SRT and WebVTT let the editor bind the cue clock and adjust its offset. Show an approximate-clock indicator wherever an assumed origin drives an edit.
- **Source** includes all original speech, including deleted takes. **Group** is the synchronized conversation. **Current Cut** follows actual output order and program audio routing, including fixed master, follow-camera, switch overrides, replacement audio, silence, trims, repeats, and reorders. Build it from the routing spans the multicam plan already produces. Inserted still cards advance output time and carry no dialogue; replacement stills change picture only; assembly indices count cards. Distinguish a transcript observed on the routed track from one inferred using another microphone. Mark coverage gaps and partial words explicitly.
- Recalculate projections after changing source offsets, routing, switches, stills, or the assembly. Projection never needs the helper. An offset change marks the session result stale: per-track words keep projecting, cross-track matches show as stale, until reconciliation finishes using valid recognition inputs under the selected bleed policy. Replacing audio invalidates the affected stream binding. Camera changes alone do not require speech recognition. Use stable occurrence references scoped to the edit revision.

## 3. Editing experience

| Editor request | Behavior |
|---|---|
| Find the line | Search exact phrases and normalized wording with punctuation/case tolerance. Filter by speaker, source, track, or occurrence. Show neighboring words, track evidence, time, and all matches. Preserve verbatim wording for display. Allow next/previous match and context playback. |
| Read and navigate | Open a keyboard-accessible transcript beside the viewer. Multicam adds a Transcript tab to its inspector. The ordinary sequence editor has no side panel today and gains one, with the presentation tools updated to match. Switch between source/group and current cut. Click a word to seek, drag or extend by keyboard to select a phrase, and follow the active word from timeline playback or scrubbing. Distinguish simultaneous speakers, partial words, and untranscribed material. |
| Trim, split, or remove words | Convert a word edge, phrase, or intervening gap into native marks or selection. Support split, trim start/end, delete range, and restore through undo. Default phrase bounds span first word start through last word end, including internal pauses. Leading/trailing padding and frame nudges are explicit. Deleting time on a mixed track also affects overlapping speech; show that in the preview. |
| Tighten pacing | Select a gap between phrases, inspect duration and waveform, specify retained duration, and protect intentional pauses. Integrate with existing silence review and routed pauses. Sequence pause protection is held in memory today; persist protections made from the transcript in the project. Display the requested and achievable duration. Handle overlapping words as concurrent speech rather than a negative pause. |
| Compare and join takes | Show matching readings with adjacent dialogue, source and occurrence, and playable context. Keep named word-range selects, stored in the project and kept after every use leaves the cut. Assemble, insert, reorder, or replace with ordered ranges from multiple inputs through the new multi-source ordered edit. A proposed transaction reports duration, cut-boundary, and export-tier changes and commits as one undoable edit. |
| Follow a script | Import or paste script text. Return candidates per beat with exact, approximate, partial, missing, and ambiguous matches. Flag a qualifier present in one take and missing in another. Review alternate takes, mark chosen passages, and use the same ordered range operation to assemble them. Expose the comparison as data so agents can apply their own editorial judgment. |
| Review restarts and fillers | Offer reviewable candidates for restarts, repeated phrases, and editor-specified filler terms. Show both surrounding passages and affected audio before accepting a cut. Support individual accept/dismiss and reviewing a batch of accepted ranges as one edit. |
| Cut multicam by dialogue | Select a speaker or word, list available angles and source-frame locations, and switch at a resolved cut point. Expose whether the operation changes a shared group interval and which replays are affected. Scope occurrence-only trims to the assembly. Keep speaker-to-angle suggestions editor-configurable. |
| Pull clips and notes | Expand a quote by word, sentence, or speaker turn, include the preceding question, and queue its captured media ranges with a name. Queue entries have no editor-set name today (sequence rows show the first file name and multicam rows the project name), so this adds one to the queue model, its row, and the queue tools. Copy a quote with source/stream, speaker, time, and occurrence references. Export source, group, or current-cut dialogue as native JSON, readable text, SRT, or WebVTT with the selected clock identified. |
| Correct attribution | Rename speakers, merge or split mistaken identities, assign selected words to a speaker, and resolve duplicate/conflicting observations. Show track evidence during review. Retain corrections across project reopen, and flag conflicts when refreshing a result. |

**Boundary review is shared with the existing editor.** A word time is an estimated speech boundary. Resolve it against indexed picture frames or audio sample clocks, then use the chosen export mode’s actual eligibility checks. Show requested, resolved, and available copy-safe alternatives, adjacent words affected, duration impact, any edge encoding, and the resulting export tier from the existing tier report. Handle variable frame rate, delayed streams, and no valid copy-safe alternative. Apply only the reviewed boundary policy. Preserve source recordings and program audio routing.

## 4. GUI, CLI, and MCP parity

The command and tool names below are proposed interfaces. Keep the same IDs, data fields, coordinate spaces, edit outcomes, and error meanings across all three. CLI targets a media file or saved project. MCP targets a live project, including an unsaved window, or uses file jobs for the same saved-file operations. File jobs run the bundled CLI through the app, so they also need the app running with local control enabled. The GUI operates on that same live document.

| Capability | GUI | CLI under `mpcut transcript` | MCP operation family |
|---|---|---|---|
| Discover inputs and capabilities | Transcript setup, audio-stream list, engine capabilities | `capabilities`, `tracks` | Read capabilities and track inventory |
| Transcribe all tracks or a subset | Explicitly start Transcriberrr, inspect progress, cancel, retry, auto-attach | Prepare a session, invoke Transcriberrr separately, then import its output JSON | Explicit live provider job; saved-file calls prepare or import |
| Import, inspect, bind, or detach | Import Transcriberrr JSON, SRT, VTT; inspect binding; relink or detach | `import`, `inspect`, `bind`, `detach` | Manage attachments and review unmatched inputs |
| Read, search, and navigate | Source/Group/Current Cut, phrase search, speaker filters, seek | `read`, `search`, `locate` | Paged read/search/locate; seek or select in live editor |
| Review takes or script | Compare passages, align script, review suggestions | `compare`, `align-script`, `suggest` | Compare candidates, align beats, list suggested ranges |
| Correct metadata | Edit speaker/text, resolve uncertain matches | `correct` with a typed change | Correct metadata with revision and undo |
| Select, review and edit | Marks, named selects, preview, apply, undo | `select`, `plan`, `apply` | Resolve word selections, plan, commit, and native undo |
| Deliver excerpts or transcript | Named queue entry and transcript export | `queue` to a named, editable excerpt snapshot; `export` | Add captured live queue entry; export transcript or file job |

- **Job record.** Transcription can outlast every existing receipt: analysis receipts are in memory and revoked when the window closes or local control turns off, file-job and replay records expire after ten minutes, and quitting cancels all jobs. Keep one durable record per transcript job on disk with its job ID, document identity, input evidence, reconciliation fingerprint, options, per-track state, owning process, and working folder. The helper runs as a child and stops when MPCut quits or is cancelled. Resume is MPCut’s: it resubmits tracks whose complete recognition key has no stored result, then reconciles. A track interrupted partway starts over. Transcriberrr’s own `--resume` is not used, since it is keyed by path and reruns a whole session. On relaunch MPCut lists resumable jobs and reattaches completed results through the same fingerprint check as a live completion. The record follows an untitled project through its first save and Save As, as its transcript store does. A local-control toggle or a regenerated project handle revokes agent access, not the job.
- **CLI.** Keep MPCut and Transcriberrr independently invocable. MPCut prepares selected audio streams and a session manifest. The user or script invokes Transcriberrr on that manifest, then passes its JSON result to MPCut for import, search, or editing. A transcript from a separate Transcriberrr run can also be imported directly. Preparation, reading, and editing never initiate recognition or a model download. Report failures at the command that owns them. Use structured JSON, explicit input/output paths, and the existing project and time-space conventions.
- CLI edit planning is read-only. `apply` and `correct` take `--out-project FILE` or `--in-place`, as `still` does. In-place verifies the SHA-256 of the project bytes it read and publishes atomically. CLI queue writes one named, editable project snapshot per excerpt. Preserve ordered clip pieces in sequences and assembly occurrences, switches, offsets, and program audio routing in multicam. Export each snapshot as one movie using the project export path. Use the same snapshot semantics in the GUI and MCP.
- **MCP.** Add a small set of action-style tools, as `sequence_clip_edit` / `sequence_range_edit` / `timeline_selection_set` / `playback_transport_control` / `workspace_layout_set` does, rather than one tool per verb, plus `transcript_file_*` for saved files. Each needs a descriptor in `MCPResources`, a dispatch branch, a return contract in the reference generator, coverage rows, and Go integration tests. A request must answer within five minutes and four mebibytes, so every long operation returns a job at once and every transcript read, search, and evidence listing is paged.
- Live MCP requests carry the project handle, expected timeline and transcript-state revisions, result identity, stable word and occurrence IDs, and operation ID where applicable. Reply with resolved ranges, affected occurrences, history action, resulting revision, or job ID. Enforce current local-control settings, cancellation, and existing retry semantics.
- **Completion race.** Persist a reconciliation fingerprint over track membership, stream evidence, channels, recognition scope, offsets, roles, speaker hints, and reconciliation options. Echo it in the result. At attach time, atomically compare it with the live configuration under the document mutation guard. If it differs, retain track outputs with valid recognition keys, mark the merge stale, and schedule reconciliation against the current configuration, rerunning affected masked inputs when required. Repeat the check on completion and after resume. A timeline-only reorder simply reprojects the valid result. Partial jobs retain explicit coverage gaps.
- Import the current Transcriberrr native JSON directly, with word or segment precision, declared clocks, and supplied speaker/track evidence. SRT and WebVTT preserve cue timing and explicit speaker labels. Cue-only documents support cue selection. Allow export without recognition.

**Fixtures and measures**

- Neither repository has a recorded speech fixture. Record a short, licence-clear interview set: two cameras, one isolated lav, a late-starting camera with delayed audio, an interruption, and three readings of a scripted line. Label words, speakers, and overlaps by hand.
- **Sample-zero fixture.** A file with a click at a known source time and AAC priming, plus one with a delayed audio stream. The click’s position in MPCut’s extracted audio and on MPCut’s source clock must agree within one 16 kHz sample. Both repositories decode the contract examples identically.
- Deterministic tests use a stub helper that replays fixture results and run everywhere. Tests against the real helper need the installed app and multi-gigabyte models, so they run only where those are present and are reported separately.
- Before milestone 3, run the real helper on the labeled set and record the baseline here: word timing error, attribution mistakes, duplicate utterances, missed overlaps, and real-time factor per engine. Use the same run to decide bleed handling before the cache key is fixed: transcribe the isolated tracks muted, as today, and unmuted with duplicate candidates reconciled using lexical, timing, and track evidence, and compare. Record acceptance thresholds from the baseline before evaluating mixed-track reconciliation.
- Measure opening, searching, and paging a multi-hour, multi-track project, and the history cost of corrections.
- Publish CLI help, generated tool schemas and reference, the offline guide, and runnable examples for one ordinary and one multicam project. The GUI walkthrough is manual except where the Accessibility-driven script covers it.

**Required acceptance scenarios**

1. Transcribe two cameras and an isolated lav by default. Camera B starts late and contains a line recorded only on that off-air camera. Find the line, preserve a guest interruption, and locate each word or coverage gap. While the host speaks on the lav, record just a cough on Camera B. Its activity must never count as a recognized host word. Selective recognition must label the skipped track.
2. Use a fixed lav, a switch-specific mic override, a silent interval, a replay, a partial word, a still card, and a reorder. Check Source, Group, and Current Cut. Change an offset both after attachment and during reconciliation. Verify stale merges cannot become current. For independent recognition assert zero recognition reruns. For mute-first assert that only tracks with changed effective masks rerun. Verify corrected speaker/text anchors under the selected policy.
3. Search three readings of a scripted line, identify a missing qualifier, select parts of two takes, preview an unsafe word boundary and its tier change, and apply the chosen plan in one undo step. Export and inspect the actual copy/encode result. Reopen and confirm the timeline, transcript, selects, and speaker corrections agree.
4. Import current single-source, merged-session, and segment-only native JSON, SRT, and WebVTT. Verify the 65 s session to 5 s source-part lookup, ambiguous part handling, approximate cue origins, and output-time cues for repeated passages.
