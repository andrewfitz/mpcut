# Saved projects, media files and the bundled CLI

The desktop connection runs the bundled CLI through typed MCP file jobs. Use this route for a named recording, a saved project or an explicit file-based edit. Paths refer to files on the Mac running MPCut. Supply an absolute `project_path` when reading a saved project, and set `working_directory` when an input document contains relative references. For “my current edit,” use the [live window](live-editor.md), including any unsaved changes.

| Request or CLI topic | Desktop route |
| --- | --- |
| Help, version, multicam template | `cli_version_read` reports the executable build ID, supported project schema versions and detector capabilities. `cli_help_read` without a topic returns its command inventory. Supply an advertised topic for a smaller result. The CLI's `multicam` topic provides help and a template. Camera editing is available through live tools and saved-project edits. |
| Inspect picture, sound or timing | `project_file_inspect` reads saved timelines. `media_file_inspect` reads stream metadata or a bounded window of frames, keyframes or audio packets. Use `waveform_file_envelope_read` with an absolute audio stream index and column count for a signed envelope. |
| Review a saved cut or camera interval | Use `timeline_file_range_map` to map ranges and `history_file_compare` to compare two saved projects. Use `multicam_file_sync_suggest` for sync evidence and `multicam_file_switch_coverage_read` for picture and routed audio through the next group switch. |
| Analyze shots, silence or cached data | `scenes_file_scan` detects shots. `scenes_file_export` writes grouped footage. `silence_file_scan` detects pauses. `silence_file_plan` computes retained ranges and `silence_file_export` writes shortened media. Use `silence_padding_per_side_seconds` for seconds retained on each side of a cut (default 0.2). On a new scan, `silence_max_blip_seconds` sets the longest isolated sound to bridge, from 0 to 1 second. Zero disables bridging. `analysis_file_sidecar_inspect` lists saved analysis. `analysis_file_sidecar_build` builds the requested sections. On supporting builds, `project_file_media_refresh` checks media referenced by a saved project. |
| Work with a saved transcript | The `transcript_file_*` tools run transcript operations on saved inputs. Use an existing JSON, SRT or WebVTT file for import. For new recognition on a saved input, use `transcript_file_job_prepare` to stage audio, run it with `transcript_file_job_run`, then import the result. For recognition owned by an open document, use the live `transcript_editor_job_start` workflow. |
| Extract pictures | `review_file_frames_export` writes images and a manifest to a new directory. Select JPEG, PNG or TIFF for supported sources. To view frames directly, start `review_file_frame_read` with `at` or up to 12 `times`, poll its job, then call `review_file_frame_result_read` for the JPEG image blocks. Add `region` to read part of a frame at its own pixels, or `max_edge` for a larger whole frame. Transcript file reads return compact rows; set `request.lines` on a words read for one row per utterance, or `request.verbose` for full records. Choose explicit times or representative scene/take samples. For camera comparisons read angle availability and group time from the manifest. |
| Produce one movie | `export_file_project_render` renders a saved project. `export_file_clips_join` joins ordered clips. `export_file_soundtrack_replace` supplies replacement sound. A project takes a separate output path. A structured edit carries its own output and ordered clips. Inspect the advertised track, soundtrack replacement, mode and container options. When available, `space_clips` sets render-time gaps with `source` or a nonnegative rational duration. To write the spacing into a saved project, use `timeline_file_clips_space`. |
| Repeat ranges or produce many files | `export_file_ranges_join` joins ordered, possibly repeated ranges from one source. `export_file_ranges_separate` writes separate numbered outputs. Use `dry_run` to preview eligible settings, ordering and destinations. Inspect partial successes before retrying a batch. |
| Exchange editable projects | `project_file_convert` converts a saved project for MPCut, Resolve, Premiere or Final Cut. Check supported direction, warnings, host prerequisites and any requested flattening. `project_file_resolve_export` writes an editable timeline. `project_file_resolve_import` also imports it into the open Resolve project. |

Read the start receipt's `job_id` and poll `file_job_status_read` until succeeded, failed, cancelled, needs_review or outcome_unknown. After a standalone worker reconnect, look up the original UUID. Inspect the destination if the recorded outcome is unknown. For cancellation use `file_job_cancel` and continue polling. Read the inline result or output text when present. For a paged result, start `file_job_result_read` at offset zero, decode each base64 page, advance to its `next_offset` until `done`, then concatenate the decoded bytes before parsing JSON. Keep the original receipt and UUID for an identical retry. Once the result has been collected, `file_job_release` frees its payload and preserves the receipt.

For an ordinary saved-project export, dry-run `export_file_project_render` on the saved path. Send its `plan_token` with the render request to bind the approval to that project, media, output and settings. If the token is stale, preflight the changed inputs again.

Use `tiles_file_pending_read` to recover a saved Check Tiles review. Stage the complete choices object with its review token, then approve using the token for the staged choices. To verify a mask or assignment edit, inspect `participant_changes` in `history_file_compare` and use `review_file_frame_read` on the affected program occurrence.

## Saved timeline edits

Use `project_file_create` and `project_file_edit` with an ordered request and a new output project. `silence_file_shorten` writes a shortened editable timeline. Keep individual sequence pauses with their reported IDs in `protect_pauses`. The `still_file_*` operations and `timeline_file_gap_insert` and `timeline_file_clips_space` edit saved placements. For multicam review choose `clock: "assembly"` for program frames or `"group"` for angle comparisons. For batch output use `base_name` and `subfolder`.

A saved `.cut` is one JSON text file that can be kept in Git and changed as text. Edit the clips and other edit fields, leave `history`, `media_snapshot` and `refs` alone, give a new clip an `id` no other clip has, then read the file with `project_file_inspect`. MPCut drops undo history that no longer matches the edit. To merge branches saved by MPCut, the clone needs `git config merge.mpcut.driver "mpcut project merge %O %A %B"` and the `.gitattributes` line `*.cut merge=mpcut`.

Use `retain_pauses` to set a total retained duration for selected pause IDs. Use `take_boundaries` in a project scan or plan without an output movie to add take splits in the reported timeline clock. Render results can include `cut_map.occurrences`, with individual uses preserved inside shared render segments.
